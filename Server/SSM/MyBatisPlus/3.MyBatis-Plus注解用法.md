# 一、`MyBatisPlus` 提供的注解

[MyBatisPlus 注解配置](https://baomidou.com/reference/annotation/ "注解配置")

| 注解                 | 作用                                                         | 使用位置       |
| -------------------- | ------------------------------------------------------------ | -------------- |
| `@MapperScan`        | 指定 `Mapper` 接口所在的包，批量扫描并注册 `Mapper Bean`     |                |
| `@Mapper`            | 标记 `Mapper` 接口，使其能够被 `MyBatis` 扫描并注册为 `Bean` |                |
| `@Param`             | 为 `Mapper` 接口方法的参数指定名称，方便在 `SQL 或 XML 中通过 `#{参数名}` 引用 |                |
| `@Alias`             | 为 `Java` 类型指定别名，在 `MyBatis` 配置中可以使用别名代替类的全限定名 |                |
|                      |                                                              |                |
| `@TableName`         | 指定实体类对应的数据库表名                                   | 类             |
| `@TableId`           | 指定实体类的主键字段及主键生成策略                           | 属性           |
| `@TableField`        | 指定实体类属性与数据库字段的映射关系                         | 属性           |
| `@TableLogic`        | 标记逻辑删除字段，删除时执行逻辑删除                         | 属性           |
| `@Version`           | 标记乐观锁版本号字段                                         | 属性           |
| `@EnumValue`         | 指定枚举类中映射到数据库的属性值                             | 枚举属性或方法 |
| `@OrderBy`           | 指定查询结果的默认排序方式                                   | 属性           |
| `@KeySequence`       | 指定数据库序列名称，用于生成主键                             | 类             |
| `@InterceptorIgnore` | 指定 `Mapper` 或方法忽略某些 `SQL` 拦截器                    | 类、方法       |



## 1.1 `@TableName` 数据库表名

该注解用于指定实体类对应的数据库表名。当实体类名与数据库表名不一致，或者实体类名不是数据库表名的驼峰写法时

默认会将实体类名转换为数据库表名，默认开启驼峰转下划线规则，如 `UserOrder -> user_order`

如果需要自定义表名，可以使用

```java
@TableName("sys_user")
public class User {
    private Long id;
    private String name;
    private Integer age;
    private String email;
}
```

常用属性：

| 属性               | 作用                          |
| ------------------ | ----------------------------- |
| `value`            | 指定表名                      |
| `schema`           | 指定数据库 Schema             |
| `keepGlobalPrefix` | 是否保留全局表名前缀          |
| `resultMap`        | 指定 XML 中定义的 `ResultMap` |
| `autoResultMap`    | 是否自动构建 `ResultMap`      |
| `excludeProperty`  | 指定排除映射的实体类属性      |



## 1.2 `@TableId` 主键字段

该注解用于标记实体类中的主键字段，并配置主键生成策略

```java
@TableName("sys_user")
public class User {
    @TableId(value = "user_id", type = IdType.AUTO)
    private Long id;
    private String name;
}
```

常用属性：

| 属性    | 类型     | 默认值        | 作用                 |
| ------- | -------- | ------------- | -------------------- |
| `value` | `String` | `""`          | 指定数据库主键字段名 |
| `type`  | `IdType` | `IdType.NONE` | 指定主键生成策略     |

>   `IdType` 常用枚举：
>
>   | 枚举值        | 作用                                                         |
>   | ------------- | ------------------------------------------------------------ |
>   | `AUTO`        | 数据库自增<br />数据库主键类型为数字，并且 `AUTO_INCREMENT`  |
>   | `NONE`        | （默认值）未设置主键策略，使用全局配置<br />可以在 `application.yml` 全局配置修改 |
>   | `INPUT`       | 手动输入主键                                                 |
>   | `ASSIGN_ID`   | 使用雪花算法生成 `ID`<br />数据库主键类型需为 `BIGINT / VARCHAR(64)` |
>   | `ASSIGN_UUID` | 使用 `UUID` 生成主键                                         |

>   在 `application.yml` 配置全局主键生成策略
>
>   ```yaml
>   mybatis-plus:
>     global-config:
>       db-config:
>         id-type: auto    # 自动生成 id
>   ```
>
>   如果使用自增，数据库主键也需要使用 `AUTO_INCREMENT`



## 1.3 `@TableField` 非主键字段

该注解用于标记实体类中的非主键字段，它告诉 `MyBatis Plus` 如何映射实体类字段到数据库表字段。如果你的实体类字段名遵循驼峰命名规则，并且与数据库表字段名一致，你可以省略这个注解

```java
@TableField(value = "department_name", exist = false)
private String departmentName;
```

常用属性：

| 属性             | 作用                                  |
| ---------------- | ------------------------------------- |
| `value`          | 指定数据库字段名                      |
| `exist`          | 是否为数据库表字段                    |
| `select`         | 查询时是否查询该字段                  |
| `fill`           | 指定字段自动填充策略<br />`FieldFill` |
| `update`         | 指定更新时的字段表达式                |
| `insertStrategy` | 插入时的字段策略                      |
| `updateStrategy` | 更新时的字段策略                      |
| `whereStrategy`  | `WHERE` 条件中的字段策略              |
| `jdbcType`       | 指定 `JDBC` 类型                      |
| `typeHandler`    | 指定类型处理器                        |

>   `FieldFill` 常用枚举：
>
>   | 枚举值          | 作用             |
>   | --------------- | ---------------- |
>   | `DEFAULT`       | 默认不处理       |
>   | `INSERT`        | 插入时填充       |
>   | `UPDATE`        | 更新时填充       |
>   | `INSERT_UPDATE` | 插入和更新时填充 |



## 1.4 `@TableLogic` 逻辑删除字段

用于配置逻辑删除字段

```java
// value = "0", delval = "1" 这里使用字符串就行，isDeleted 的类型是 Integer，最后转成 sql 会是数字的 
@TableLogic(value = "0", delval = "1")
private Integer isDeleted;
```

| 属性     | 作用             |
| -------- | ---------------- |
| `value`  | 未删除时的字段值 |
| `delval` | 删除时的字段值   |

执行删除操作时，不会真正删除数据库记录，而是将 `is_deleted` 修改为 `1`



1.   删除操作：触发逻辑删除

     ```java
     userMapper.deleteById(1L);
     ```

     实际上执行的是

     ```sql
     UPDATE sys_user
     SET is_deleted = 1
     WHERE user_id = 1
       AND is_deleted = 0;
     ```

2.   查询操作：自动过滤已删除数据

     ```java
     userMapper.selectById(1L);
     ```

     ```sql
     SELECT *
     FROM sys_user
     WHERE user_id = 1
       AND is_deleted = 0;
     ```

3.   更新操作：自动过滤已删除数据

     ```java
     User user = new User();
     user.setUserName("admin");
     
     userMapper.updateById(user);
     ```

     ```sql
     UPDATE sys_user
     SET user_name = 'admin'
     WHERE user_id = 1
       AND is_deleted = 0;
     ```

4.   常见 `CRUD` 操作汇总

     | `Mapper` 方法      | 是否受逻辑删除影响 | 作用               |
     | ------------------ | ------------------ | ------------------ |
     | `deleteById()`     | 是                 | 转换为逻辑删除     |
     | `delete()`         | 是                 | 转换为逻辑删除     |
     | `deleteBatchIds()` | 是                 | 批量逻辑删除       |
     | `selectById()`     | 是                 | 自动过滤已删除数据 |
     | `selectList()`     | 是                 | 自动过滤已删除数据 |
     | `selectCount()`    | 是                 | 自动过滤已删除数据 |
     | `updateById()`     | 是                 | 自动过滤已删除数据 |
     | `update()`         | 是                 | 自动过滤已删除数据 |

---

>   通过 `YAML` 全局配置统一指定逻辑删除字段名、未删除值和已删除值
>
>   ```yaml
>   mybatis-plus:
>     global-config:
>       db-config:
>         logic-delete-field: isDeleted  # 逻辑删除字段名（实体类属性名）
>         logic-not-delete-value: 0      # 未删除值
>         logic-delete-value: 1          # 已删除值
>   ```



## 1.5 `@Version` 乐观锁

[乐观锁](../../../MySql/27.锁.md#`3.3.2` 乐观锁)：认为并发冲突很少发生，所以**不加锁**，在更新时检查数据是否被其他人改过。如果改过，就失败重试



1.   在需要使用乐观锁的表中添加 `version` 字段。

     ```sql
     ALTER TABLE `user`
     ADD COLUMN `version` INT NOT NULL DEFAULT 0 COMMENT '版本号';
     ```

2.   实体类添加 `@Version`

     ```java
     @Data
     @TableName("user")
     public class User {
     
         @TableId(type = IdType.AUTO)
         private Long id;
     
         private String userName;
     
         /**
          * 乐观锁版本号
          */
         @Version
         private Integer version;
     }
     ```

3.   配置乐观锁插件

     在 `MyBatis-Plus` 配置类中注册 `OptimisticLockerInnerInterceptor`

     ```java
     @Configuration
     public class MybatisPlusConfig {
     
         /**
          * MyBatis-Plus 插件配置
          */
         @Bean
         public MybatisPlusInterceptor mybatisPlusInterceptor() {
     
             MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
     
             // 乐观锁插件
             interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
     
             return interceptor;
         }
     }
     ```
     
4.   使用乐观锁更新数据

     ```java
     User user = userMapper.selectById(1L);
     
     // 修改用户状态
     user.setStatus(0);
     
     // 更新用户
     int rows = userMapper.updateById(user);
     
     if (rows == 0) {
         // 更新失败，可能是版本冲突，也可能是记录不存在
     }
     ```

     `MyBatis-Plus` 会自动处理版本号

     ```sql
     UPDATE `user`
     SET
         status = 0, version = 1
     WHERE
         id = 1 AND version = 0;
     ```




# 二、防止全表更新删除插件

```java
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        // 防止全表更新和删除
        interceptor.addInnerInterceptor(new BlockAttackInnerInterceptor());

        return interceptor;
    }
}
```

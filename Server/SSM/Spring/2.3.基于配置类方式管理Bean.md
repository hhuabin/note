| 注解             | 作用                                                         |
| ---------------- | ------------------------------------------------------------ |
| `@ComponentScan` | 组件扫描，自动发现并注册 `Bean`<br />默认扫描当前类所在的包  |
| `@Configuration` | 声明一个配置类，配置类本身也是一个组件                       |
| `@Bean`          | 将方法返回对象注册为 `Spring Bean`<br />组件 `id` 默认是方法名<br />组件类型默认是返回值的类型 |
| `@Import`        | 导入其他配置类                                               |
|                  |                                                              |



# 一、`Configuration` 定义配置类

>   使用 配置类 + 注解 就可以干掉 `xml` 配置了

1. 声明配置类

   >   替换 `xml` 配置文件以及替换扫描包标签

   ```java
   // 扫描指定包下的组件
   @ComponentScan({"com.springioc.controller", "com.springioc.service"})
   // 引用外部配置文件
   @PropertySource(value = "classpath:jdbc.properties")
   // 标注配置类
   @Configuration
   public class JavaConfiguration {
   
   }
   ```

2. 声明组件

   ```java]
   @Controller
   public class StudentController {
   
       // @Autowired
       // private StudentService studentService;
   }
   ```

   >   替换 `<bean/>` 标签

3. 测试组件有没有被注册进来

   和 `xml` 配置文件不一样，配置类使用 `AnnotationConfigApplicationContext` 创建 `IoC` 容器

   ```java
   public class SpringTest {
   
       @Test
       public void test() {
           // 创建 ioc 容器
           ApplicationContext applicationContext = new AnnotationConfigApplicationContext(JavaConfiguration.class);
           
           // 创建方式2
           // AnnotationConfigApplicationContext applicationContext = new AnnotationConfigApplicationContext();
           // applicationContext.register(JavaConfiguration.class);
           // applicationContext.refresh();
   
           // 获取Bean
           StudentController bean = applicationContext.getBean(StudentController.class);
           System.out.println("bean=" + bean);
       }
   }
   ```



# 二、`@Bean` 注解配置 `Bean`

>   `@Bean`标注方法的**返回值**是一个 `Bean`。组件 `id` 默认是方法名，组件类型默认是返回值的类型

| 属性                | 类型       | 作用                            |
| ------------------- | ---------- | ------------------------------- |
| `value`             | `String[]` | 指定 `Bean` 名称，`name` 的别名 |
| `name`              | `String[]` | 指定 `Bean` 名称及别名          |
| `autowire`          | `Autowire` | 控制自动装配模式，已不推荐使用  |
| `autowireCandidate` | `boolean`  | 是否作为自动注入的候选 `Bean`   |
| `initMethod`        | `String`   | 指定初始化方法                  |
| `destroyMethod`     | `String`   | 指定销毁方法                    |

其中最常用的是 `name`、`initMethod`、`destroyMethod` 和 `autowireCandidate`



## 2.1 `Bean` 名称配置

1.   默认名称

     默认情况下，`@Bean` 使用方法名称作为 `Bean` 名称

     ```java
     @Configuration
     public class SpringConfig {
     
         @Bean
         public UserDao userDao() {
             return new UserDao();
         }
     }
     ```

     对应 `Bean` 名称为 `userDao`

2.   指定 `Bean` 名称

     可以通过 `name` 或 `value` 指定名称

     ```java
     @Bean(name = "userDao")
     // @Bean("userDao")    // 只有一个属性的时候可以简写
     public UserDao createUserDao() {
         return new UserDao();
     }
     ```

3.   设置多个名称（别名）

     ```java
     @Bean(name = {"userDao", "userDao1", "userDao2"})
     public UserDao createUserDao() {
         return new UserDao();
     }
     ```

     -   `userDao` 是 `Bean` 的主名称。

     -   `userDao1`、`userDao2` 是它的别名。

     -   通过这些名称获取到的都是同一个 `Bean` 实例

         ```java
         UserDao dao1 = context.getBean("userDao", UserDao.class);
         UserDao dao2 = context.getBean("userDao1", UserDao.class);
         
         System.out.println(dao1 == dao2); // true
         ```



## 2.2 `@Bean` 配置组件作用域

1.   单例

     ```java
     @Bean
     @Scope("singleton")
     public UserDao userDao() {
         return new UserDao();
     }
     ```

2.   多例

     ```java
     @Bean
     @Scope("prototype")
     public UserDao userDao() {
         return new UserDao();
     }
     ```



## 2.3 初始化和销毁方法

`@Bean` 可以通过 `initMethod` 和 `destroyMethod` 指定 Bean 的初始化方法和销毁方法

1.   定义 `UserDao`

     ```java
     public class UserDao {
     
         public void findUser() {
             System.out.println("查询用户");
         }
     
         public void init() {
             System.out.println("UserDao 初始化");
         }
     
         public void destroy() {
             System.out.println("UserDao 销毁");
         }
     }
     ```

2.   配置初始化和销毁方法

     ```java
     @Configuration
     public class SpringConfig {
     
         @Bean(
             initMethod = "init",
             destroyMethod = "destroy"
         )
         public UserDao userDao() {
             return new UserDao();
         }
     }
     ```



## 2.4 `@Bean` 方法中调用其他 `Bean`

1.   通过方法参数注入（推荐）

     `Spring` 会自动从 `IoC` 容器中查找对应的 `Bean`，并注入到方法参数中

     ```java
     @Configuration
     public class SpringConfig {
     
         @Bean
         public UserDao userDao() {
             return new UserDao();
         }
     
         @Bean
         // 参数列表可以直接携带参数，参数名为组件名
         public UserService userService(UserDao userDao) {
     
             // 使用注入的 UserDao
             return new UserService(userDao);
         }
     }
     ```

     如果容器中有多个 `Bean` 可以使用 `@Qualifier`

     ```java
     @Bean
     public UserService userService(@Qualifier("userDao") UserDao userDao) {
     
         return new UserService(userDao);
     }
     ```

2.   直接调用其他 `@Bean` 方法

     也可以直接在一个 `@Bean` 方法中调用另一个 `@Bean` 方法

     ```java
     @Configuration(proxyBeanMethods = true)
     public class SpringConfig {
     
         @Bean
         public UserDao userDao() {
             return new UserDao();
         }
     
         @Bean
         public UserService userService() {
     
             // 直接调用另一个 @Bean 方法
             UserDao userDao = userDao();
     
             return new UserService(userDao);
         }
     }
     ```

     这种方式创建的对象与 `proxyBeanMethods` 有关

     -   `@Configuration(proxyBeanMethods = true)`：使用 `CGLIB` 增强配置类，从容器中获取已经注册的 `userDao` `Bean`，避免重复创建对象
     -   `@Configuration(proxyBeanMethods = false)`：不使用 `CGLIB` 增强配置类，普通的 `Java` 方法调用，会重新执行 `userDao()` 方法，创建一个新的 `UserDao` 对象



## 2.5 `@Bean` 与 `@Component` 对比

两者都可以将对象注册到 `Spring IoC` 容器，但使用场景不同。

| 对比项             | `@Bean`                  | `@Component`       |
| ------------------ | ------------------------ | ------------------ |
| 使用位置           | 方法                     | 类                 |
| `Bean` 注册方式    | 方法返回对象             | 组件扫描创建对象   |
| 是否需要组件扫描   | 不一定，需要配置类被加载 | 需要组件扫描       |
| 是否需要修改目标类 | 不需要                   | 需要添加注解       |
| 常见用途           | 第三方类、自定义对象创建 | 自己编写的业务组件 |



# 三、`@Import` 注解使用

>   `@Import` 是 `Spring` 框架中一个非常核心的注解，主要用于**将指定的类（通常是配置类或普通组件）导入到当前 `Spring` 容器中**，使其成为 `Bean` 定义

`@Import` 的 `value` 可以接收三种类型的类：

1.   普通**配置类**（带 `@Configuration`）；直接导入，里面的 `@Bean` 会生效

     ```java
     @Configuration
     public class DatabaseConfig {
         @Bean
         public DataSource dataSource() {
             return new HikariDataSource();
         }
     }
     ```

     在 `MainConfig` 上导入：

     ```java
     @Configuration
     @Import(DatabaseConfig.class)
     public class MainConfig {
     }
     ```

2.   普通**组件类**（不带 `@Configuration`）

     即使类上没有 `@Configuration`，只要被 `@Import` 导入，它本身也会被注册为一个 `Bean`（相当于加了 `@Component`）

     ```java
     // 注意：这个类没有任何注解（没有 @Component、@Service 等）
     public class User {
     
         private String name;
         private Integer age;
     
         public User() {
             System.out.println("User 无参构造器执行");
         }
     }
     ```

     >   这个 `User` 类**没有任何注解**，`@ComponentScan` 扫描不到它，但通过 `@Import` 可以注册进容器

     ```java
     @Configuration
     @Import({User.class, Order.class})
     public class AppConfig { }
     ```

     -   目标类**不需要任何注解**
     -   注册的 `Bean` 名称为**类名首字母小写**（`user`、`order`）

3.   `ImportSelector` 的实现类

     用于**动态批量导入**。实现 `selectImports` 方法，返回要导入的类名数组，`Spring` 会把这些类全部注册

     ```java
     public class MyImportSelector implements ImportSelector {
         @Override
         public String[] selectImports(AnnotationMetadata importingClassMetadata) {
             return new String[]{"com.example.A", "com.example.B"};
         }
     }
     ```

     ```java
     @Configuration
     @Import(MyImportSelector.class)
     public class MainConfig {}
     ```

>   与 `@ComponentScan` 的区别
>
>   |                    | `@Import`                    | `@ComponentScan`             |
>   | :----------------- | :--------------------------- | :--------------------------- |
>   | 导入方式           | 显式指定类                   | 扫描包路径                   |
>   | 适用场景           | 精确导入、第三方类、动态导入 | 批量扫描自己项目里的组件     |
>   | 能否导入无注解的类 | 能（直接注册为 `Bean`）      | 不能（需要 `@Component` 等） |





# 四、测试环境 中 使用自动装配

>   主要在测试类中直接**使用自动装配**

1. 导入依赖

   ```xml
   <!--junit5测试-->
   <dependency>
       <groupId>org.junit.jupiter</groupId>
       <artifactId>junit-jupiter-api</artifactId>
       <version>5.3.1</version>
   </dependency>
   
   <dependency>
       <groupId>org.springframework</groupId>
       <artifactId>spring-test</artifactId>
       <version>6.0.6</version>
       <scope>test</scope>
   </dependency>
   ```

2. 在测试环境使用 `@SpringJUnitConfig` 导入配置类

   >   这样在 测试类 也可以使用自动装配
   >
   >   不需要再通过 `AnnotationConfigApplicationContext` 创建容器了

   ```java
   import org.springframework.test.context.junit.jupiter.SpringJUnitConfig;
   
   @SpringJUnitConfig(value = {JavaConfiguration.class})      // 导入对应的 配置类
   public class SpringTest {
   
       // 自动装配
       @Autowired
       private StudentController studentController;
   
       @Test
       public void testJUnitConfig() {
           System.out.println("bean=" + studentController);
       }
   
   }
   ```

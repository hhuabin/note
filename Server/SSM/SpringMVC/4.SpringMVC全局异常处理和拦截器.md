# 一、全局异常处理机制

## 1.1 异常处理的两种方式

1. 编程式异常处理

   指在代码中显式地编写处理异常的逻辑。它通常涉及到对异常类型的检测及其处理，例如使用 **`try-catch` 块**来捕获异常，然后在 `catch` 块中编写特定的处理代码，或者在 `finally` 块中执行一些清理操作

2. 声明式异常处理

   将异常处理的逻辑从具体的业务逻辑中分离出来，通过配置等方式进行统一的管理和处理。在声明式异常处理中，开发人员只需要为方法或类标注相应的注解（如 `@Throws` 或 `@ExceptionHandler`），就可以处理特定类型的异常。相较于编程式异常处理，声明式异常处理可以使代码更加简洁、易于维护和扩展



## 1.2 基于注解异常声明异常处理

[@ExceptionHandler 笔记](./2.SpringMVC提供的注解.md#12. `@ExceptionHandler` 处理指定异常)

1. 声明异常处理控制器类，声明注解 `@ControllerAdvice`

   `config.GlobalExceptionHandler`
   
   ```java
   // 全局异常拦截器
   // 全局异常发生会走此类下的 handler 方法
   @ResponseBody
   @ControllerAdvice                     // 可以返回逻辑视图 转发和重定向的
   // @RestControllerAdvice              // @ControllerAdvice + @ResponseBody
   public class GlobalExceptionHandler {
   
       // @ExceptionHandler(异常种类)
       @ExceptionHandler(ArithmeticException.class)   // 除0异常
       public Object ArithmeticExceptionHandler(ArithmeticException ex) {
           System.out.println("除0异常");
           // 返回内容给前端
           return "exception";
       }
   
       // 全部异常，当其他的异常匹配不到才走这里
       @ExceptionHandler(Exception.class)
       public Object ExceptionHandler(Exception ex) {
           String message = ex.getMessage();
           System.out.println("message=" + message);
           return message;
       }
   }
   ```
   
   ```java
   @RestController
   public class UserController {
   
       @GetMapping("arithmetic")
       public String ArithmeticExceptionController() {
           int i = 1 / 0;
           return "ok";
       }
   
       @GetMapping("exception")
       public String exception() {
           String name = null;
           name.toString();
           return "ok";
       }
   }
   ```



# 二、`Interceptor` 拦截器

>   拦截器由 `SpringMVC` 提供；此外还有个[过滤器](../../JavaWeb/2.过滤器.md)的概念，过滤器由 `Java Web / Servlet` 提供

## 2.1 拦截器介绍

`Interceptor` 主要有三个方法

1. `preHandle()`
2. `postHandle()`
3. `afterCompletion()`

| 方法                | 执行时机                            | 作用                         |
| ------------------- | ----------------------------------- | ---------------------------- |
| `preHandle()`       | `Controller` 执行之前               | 请求预处理，可以决定是否放行 |
| `postHandle()`      | `Controller` 执行之后，视图渲染之前 | 对 `ModelAndView` 进行处理   |
| `afterCompletion()` | 整个请求处理完成之后                | 资源清理、记录日志等         |

```tex
// 执行顺序
preHandle()
 ↓
Controller
 ↓
postHandle()
 ↓
afterCompletion()
```



## 2.2 拦截器使用

1. 创建 `interceptor.MyInterceptor` 类，实现 `HandlerInterceptor` 接口

   ```java
   public class MyInterceptor implements HandlerInterceptor {
   
       /**
        * 在处理请求的目标 handler 方法前执行。如登录保护，权限处理
        * @param request 请求对象
        * @param response 响应对象
        * @param handler handler 方法
        * @return 返回 true 放行，false 拦截
        * @throws Exception
        */
       @Override
       public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
   
           System.out.println("request = " + request + ", response = " + response + ", handler = " + handler);
           // 返回 true-放行，返回 false-不放行
           return true;
       }
   
       /**
        * 在 handler 方法执行之后触发的方法
        * 用法：对结果处理，对敏感词汇处理
        * @param request 请求对象
        * @param response 响应对象
        * @param handler handler 方法
        * @param modelAndView 视图和共享域对象
        * @throws Exception
        */
       @Override
       public void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler, ModelAndView modelAndView) throws Exception {
           System.out.println("MyInterceptor.postHandle");
       }
   
       // 渲染视图之后执行（一定执行）
   
       /**
        * 整体处理完毕
        * @param request
        * @param response
        * @param handler
        * @param ex 如果 handler 报错就是异常对象
        * @throws Exception
        */
       @Override
       public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) throws Exception {
           System.out.println("MyInterceptor.afterCompletion");
       }
   }
   
   ```

2. 在配置类中添加拦截器

   `config.WebMvcConfig`

   ```java
   @EnableWebMvc  // json 数据处理，必须使用此注解，因为他会加入 json 处理器
   @Configuration
   @ComponentScan("com.springmvc")
   public class WebMvcConfig implements WebMvcConfigurer {
   
       // 添加拦截器
       @Override
       public void addInterceptors(InterceptorRegistry registry) {
           // 将拦截器添加到Springmvc环境，默认拦截所有 Springmvc 分发的请求
           // registry.addInterceptor(new MyInterceptor());
   
           registry.addInterceptor(new MyInterceptor())
                   // 设置拦截路径
                   .addPathPatterns("/user/*", "/user/**")
                   // 设置排除路径
                   .excludePathPatterns(
                           "/user/login",
                           "/user/register",
                           "/user/public/**",
                           "/user/bin"
                   );
       }
   }
   
   ```



## 2.3 拦截器配置说明

| 方法                            | 说明                   |
| ------------------------------- | ---------------------- |
| `addInterceptor(interceptor)`   | 注册一个拦截器         |
| `addPathPatterns(patterns)`     | 设置需要拦截的请求路径 |
| `excludePathPatterns(patterns)` | 设置排除拦截的请求路径 |

1. 精准拦截

   ```java
   // 添加拦截器
   @Override
   public void addInterceptors(InterceptorRegistry registry) {
       // 将拦截器添加到Springmvc环境，默认拦截所有 Springmvc 分发的请求
       // registry.addInterceptor(new MyInterceptor());
   
       registry.addInterceptor(new MyInterceptor())
               // 设置拦截路径
               .addPathPatterns("/user/*", "/user/**")
               // 设置排除路径
               .excludePathPatterns(
                       "/user/login",
                       "/user/register",
                       "/user/public/**",
                       "/user/bin"
               );
   }
   ```

2. 多个拦截器的顺序问题

   ```java
   public void addInterceptors(InterceptorRegistry registry) {
       
       registry.addInterceptor(new MyInterceptor1());
       
       registry.addInterceptor(new MyInterceptor2());
       
   }
   ```

   >   `MyInterceptor1` 先注册；先注册优先级更高

   执行顺序：
   
   1. `preHandle1`
   2. `preHandle2`
   3. `postHandle2`
   4. `postHandle1`
   5. `afterCompletion2`
   6. `afterCompletion1`

# 索引

> 索引是把**双刃剑**，可提高查询效率，但也会降低插入和更新的速度并占用磁盘空间。



## 1.1索引分类

| 索引类型               | 作用                                                         |
| ---------------------- | ------------------------------------------------------------ |
| 主键索引 `PRIMARY KEY` | 唯一标识一条数据（给表建立**主键**的时候会自动给主键添加主键索引） |
| 唯一索引 `UNIQUE`      | 数据不能重复（给字段建立**唯一性约束**的时候会自动给字段添加唯一索引） |
| 普通索引 `INDEX`       | 提高查询速度                                                 |
| 联合索引 `INDEX`       | 多个字段一起建立索引                                         |
| 全文索引 `FULLTEXT`    | 用于文本搜索                                                 |

适合建立索引的位置：`WHERE`、`JOIN`、`ORDER BY`、`GROUP BY`



## 1.2创建索引

```sql
CREATE TABLE sys_user (
    id BIGINT,
    username VARCHAR(50),
    email VARCHAR(100),
    age INT,
    city VARCHAR(50),
    content TEXT
);
```

> 创建索引时，不指定索引名就采用字段名，索引名一般以 `idx_` 开头，如 `idx_id`、`uk_idx_id`（唯一索引）、`mul_idx_id_name`（联合索引）

1. 创建**主键索引**

    建表时添加

    ```sql
    # 添加主键
    CREATE TABLE sys_user (
        id BIGINT PRIMARY KEY,
        username VARCHAR(50)
    );
    
    CREATE TABLE sys_user (
        id BIGINT,
        username VARCHAR(50),
        PRIMARY KEY (id)
    );
    ```

    已有表添加主键

    ```sql
    ALTER TABLE sys_user
    ADD PRIMARY KEY (id);
    ```

2. 创建**唯一索引**

    建表时添加

    ```sql
    # 添加唯一性约束
    CREATE TABLE sys_user (
        id BIGINT,
        username VARCHAR(50) UNIQUE
    );
    
    CREATE TABLE sys_user (
        id BIGINT,
        username VARCHAR(50),
        UNIQUE INDEX uk_username (username)
    );
    ```

    已有表添加主键

    ```sql
    CREATE UNIQUE INDEX uk_username
    ON sys_user (username);
    
    # 或
    ALTER TABLE sys_user
    ADD UNIQUE INDEX uk_username (username);
    ```

3. 创建**普通索引**

    建表时添加

    ```sql
    CREATE TABLE sys_user (
        id BIGINT,
        username VARCHAR(50),
        INDEX uk_username (username)
    );
    ```

    已有表添加主键

    ```sql
    CREATE INDEX idx_age
    ON sys_user (age);
    
    ALTER TABLE sys_user
    ADD INDEX idx_age (age);
    ```

4. 创建**联合索引**

     建表时添加

     ```sql
     CREATE TABLE sys_user (
         id BIGINT,
         username VARCHAR(50),
         age INT,
         INDEX idx_username_age(username, age)
     );
     ```

     已有表添加主键

     ```sql
     CREATE INDEX idx_age_city
     ON sys_user (age, city);
     
     # 或
     ALTER TABLE sys_user
     ADD INDEX idx_age_city (age, city);
     ```

     > 联合索引：`index(a,b,c)`，索引存储顺序：**先按 a 排序，a 相同再按 b 排序，b 相同再按 c 排序**
     >
     > **最左前缀原则**：查询条件要匹配索引最左边的连续字段，索引才会生效
     >
     > ```sql
     > select * from t where a=? and b=? and c=?;    # 可以走索引 a,b,c
     > 
     > select * from t where a=? and b=?;            # 可以走索引 a,b
     > 
     > select * from t where a=? and c=?;            # 可以走索引 a
     > 
     > select * from t where b=? and c=?;            # 没有a，不能走 index(a,b,c) 索引
     > ```

5. 创建**全文索引**

    `FULLTEXT` 全文索引可以用于全文搜索，并且只为 `CHAR`、`VARCHAR` 和 `TEXT` 列创建索引。索引总是对整个列进行，不支持局部(前缀)索引

    建表时添加

    ```sql
    CREATE TABLE sys_user (
        id BIGINT,
        username VARCHAR(50),
        age INT,
        FULLTEXT futxt_idx_username(username)
    );
    ```

    已有表添加主键

    ```sql
    CREATE FULLTEXT INDEX idx_content
    ON sys_user (content);
    ```



## 1.3查看索引

1. 查看一张表的所有索引

    ```sql
    SHOW INDEX FROM sys_user;
    
    # 或
    SHOW KEYS FROM sys_user;
    ```

    

## 1.4删除索引

> 删除表中的列时，如果要删除的列为索引的组成部分（联合索引），则该**列也会从索引中删除**
>
> 如果组成索引的所有列都被删除，则**整个索引将被删除**

1. 删除**主键索引**

    ```sql
    ALTER TABLE sys_user
    DROP PRIMARY KEY;
    ```

2. 删除**唯一索引、普通索引、联合索引**

    > 删除唯一索引也会**删除掉唯一性约束**

    ```sql
    DROP INDEX 索引名
    ON 表名;
    
    # 例如
    DROP INDEX uk_username
    ON sys_user;
    
    # 或
    ALTER TABLE sys_user
    DROP INDEX idx_username;
    ```

    > 联合索引的问题：如果联合索引关联有三个字段名，如 `idx_name_age_sex`，删除掉一个列，联合索引会重置关联为剩下的两个字段，索引名不变

5. 删除全文索引

    ```sql
    DROP INDEX idx_content ON sys_user;
    ```




# `MySQL 8.0` 新特性

## 2.1支持降序索引（仅限 `InnoDB` 存储引擎）

> 以前的 `MySQL` 版本中，索引主要按照**升序**存储。
>
> `MySQL 8.0` 支持在创建索引时为索引列指定 `ASC` / `DESC`，主要用于优化 `ORDER BY`，尤其适合联合索引中不同字段具有不同排序方向的场景

1. 创建降序索引

    ```sql
    CREATE INDEX idx_age_desc
    ON user (age DESC);
    ```

2. 创建多列降序索引

    降序索引真正比较有价值的地方，是**联合索引**

    > **降序索引列的顺序是根据 `ORDER BY` 定义的**，如 `ORDER BY b DESC, a ASC` 的降序索引为 `INDEX idx_b_a (b DESC, a ASC)`
    
    ```sql
    CREATE INDEX idx_age_id
    ON user (age DESC, id ASC);
    ```
    
    ```sql
    # 年龄从大到小。同年龄时 id 从小到大
    SELECT *
    FROM user
    ORDER BY age DESC, id ASC;
    ```
    
3. 查看降序索引

    ```sql
    # 其中 Collation 列，展示 D 的表示降序（Descending），A 表示升序（Ascending）
    SHOW INDEX FROM sys_user;
    ```



## 2.2 隐藏索引 `Invisible Index`

隐藏索引：索引还存在，但是优化器默认不会使用它

用于：直接删除索引有风险，可以使用隐藏索引，测试没有索引的情况是否严重影响性能，确认无误后再删除

> 主键索引不能隐藏，如果没有主键索引，非空且唯一会成为隐式主键，也不能设置为隐藏索引（聚簇索引不可隐藏）

1. 创建表时添加隐藏索引（设置为不可见状态）

    ```sql
    CREATE TABLE user (
        id BIGINT PRIMARY KEY,
        name VARCHAR(50),
        INDEX idx_name (name) INVISIBLE       # 不可见
    );
    ```

2. 切换索引为不可见状态（隐藏索引）

    ```sql
    ALTER TABLE user
    ALTER INDEX idx_name INVISIBLE;
    ```

3. 切换索引为可见状态（恢复索引）

    ```sql
    ALTER TABLE user
    ALTER INDEX idx_name VISIBLE;
    ```

4. 使用隐藏索引

    默认情况下，优化器不会考虑 隐藏索引

    ```sql
    SELECT @@optimizer_switch;
    # 输出如果有 use_invisible_indexes=off 说明优化器不会考虑 隐藏索引
    
    SET SESSION optimizer_switch = 'use_invisible_indexes=on';        # 优化器可见隐藏索引，隐藏索引将失效
    ```



# 索引的设计原则

## 3.1适合添加索引的11种情况

1. 字段有唯一性限制。开发中：业务上具有唯一特性的字段，即使是组合字段，也必须建成唯一索引

    ```sql
    CREATE TABLE sys_user (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        username VARCHAR(50) NOT NULL,
        phone VARCHAR(20) NOT NULL,
        
        UNIQUE KEY uk_phone (phone)
    );
    ```

2. 频繁作为 `WHERE` 查询条件的字段

    ```sql
    SELECT *
    FROM student_info
    WHERE student_id = 1002;
    ```

    适合给 `student_id` 建立索引

3. 经常 `ORDER BY`、`GROUP BY` 的列

    ```sql
    SELECT *
    FROM student_info
    WHERE class_id = 1
    ORDER BY create_time DESC;
    ```

    对于多个字段满足条件的，联合索引可能比单独建立两个索引更合适

    ```sql
    CREATE INDEX idx_class_create_time
    ON student_info(class_id, create_time);       # 联合索引
    ```

4. `UPDATE`、`DELETE` 的 `WHERE` 条件列

    ```sql
    UPDATE student_info SET name = 'bin'
    WHERE  student_id = 1002;
    ```

    适合给 `student_id` 建立索引

5. `DISTINCT` 字段需要创建索引

6. 多表 `JOIN` 连接操作时，连接字段需要创建索引

7. 使用列的类型小的创建索引：如索引字段能用 `INT UNSIGNED` 类型就不要用 `BIGINT` 类型

    **索引字段的数据类型越小，索引通常越小**，一个索引页能存更多数据，从而减少存储空间和可能的磁盘 I/O，提高查询效率

8. 使用字符串的前缀创建索引

    ```sql
    # email(10) 表示只取 email 字符串的前 10 个字符建立索引
    CREATE INDEX idx_email
    ON sys_user(email(10));
    ```

9. 区分度高（散列性高）的列适合作为索引

    ```sql
    WHERE gender = '男'
    ```

    `gender` 不是男就是女，10000 条数据的表，男女几乎各一半一半，这类区分度不高的字段，即使创建了索引也没有意义

10. 使用最频繁的列放到**联合索引**的左侧

    如果有两个查询

    ```sql
    SELECT *
    FROM orders
    WHERE user_id = 1001;
    
    SELECT *
    FROM orders
    WHERE user_id = 1001
    AND status = 1;
    ```

    公共字段是`user_id`， 因此创建联合索引时，可以将 `user_id` 放在最左侧：

    ```sql
    CREATE INDEX idx_user_status
    ON orders(user_id, status);
    ```

    这样两个查询都能用上索引

11. 在**多个字段**都要创建索引的情况下，**联合索引**优于单值索引

     ```sql
     SELECT *
     FROM orders
     WHERE user_id = 1001
     AND status = 1;
     ```

     ```sql
     # ✅联合索引
     CREATE INDEX idx_category_status
     ON product(category_id, status);
     ```



## 3.2限制索引的数目

在实际工作中，我们也需要注意平衡，索引的数目不是越多越好。我们需要限制每张表上的索引数量，建议**单张表索引数量不超过6个**



## 3.3哪些情况不适合创建索引

1. 在 `WHERE` 中使用不到的字段，不要创建索引

2. **数据量小**的表最好不要使用索引

3. 有大量重复数据的列上不要是使用索引；

    如 `gender` 列，一般重复度超过 10% 的时候就不需要索引了

4. 避免对经常更新的表创建过多的索引

5. 不建议使用无序的值作为索引

    例如身份证，`UUID`

6. 删除不再使用或很少使用的索引

7. 不要定义冗余或重复的索引

    如果有联合索引 `idx (a,b)`，就不需要索引 `idx (a)` 了

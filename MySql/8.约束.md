# 约束

为了**保证数据的完整性**，SQL规范以约束的方式对**表数据进额外的条件限制**

**数据完整性**：是指数据的精确性和可靠性。它是防止数据库中存在不符合语义规定的数据和防止因错误信息的输入输出造成无效操作或错误信息而提出的。

| 数据完整性的主要类型 | 含义                             | MySQL 常用手段                           |
| -------------------- | -------------------------------- | ---------------------------------------- |
| **实体完整性**       | 保证每一行数据能够被唯一标识     | `PRIMARY KEY`                            |
| **域完整性**         | 保证字段的值符合规定的范围和类型 | 数据类型、`NOT NULL`、`DEFAULT`、`CHECK` |
| **参照完整性**       | 保证表与表之间的关联关系正确     | `FOREIGN KEY`                            |
| **用户定义完整性**   | 保证数据符合具体业务规则         | `CHECK`、触发器、程序逻辑等              |



## 1.`NOT NULL` 非空约束

表示该字段必须有值，不能是 `NULL`，`''`、`0` 这些不影响

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY,
    age INT NOT NULL,           # 非空约束
    name VARCHAR(50) NOT NULL   # 非空约束
);
```

1. 建表后添加非空约束（该语法是修改字段类型的，别漏了字段类型）

    ```sql
    # 此时需要保证原表中的 `name` 列没有 `NULL` 值，否则，修改不生效
    ALTER TABLE user
    MODIFY COLUMN name VARCHAR(100) NOT NULL;
    ```

2. 删除非空约束

    ```sql
    # 此时需要保证原表中的 `name` 列没有 `NULL` 值，否则，修改不生效
    ALTER TABLE user
    MODIFY COLUMN name VARCHAR(100) NULL;
    ```



## 2.`UNIQUE` 唯一性约束

允许出现多个`NULL`

1. `CREATE TABLE`列级约束

    ```sql
    CREATE TABLE user (
        id BIGINT UNIQUE,            # 唯一性约束（列级约束）
        email VARCHAR(25) UNIQUE     # 唯一性约束
    );
    ```

2. 表级唯一约束

    `[CONSTRAINT 约束名] UNIQUE (字段名)`：`[CONSTRAINT 约束名]` 可以被省略，约束名默认与**列名**相同；唯一性约束可以有多个，所以，有必要可以指定约束名

    ```sql
    CREATE TABLE user (
        id BIGINT PRIMARY KEY,
        email VARCHAR(25),
        CONSTRAINT uk_email UNIQUE (email)        # [CONSTRAINT 约束名] UNIQUE (字段名)，唯一性约束名字一般带 uk
    );
    ```

3. 表级联合唯一约束

    表级 `UNIQUE` 最重要的用途是**多个字段组合起来唯一**。

    例如，一个部门中的员工编号不能重复

    ```sql
    CREATE TABLE employee (
        id BIGINT PRIMARY KEY,
        department_id BIGINT,
        employee_no VARCHAR(20),
    
        CONSTRAINT uk_dept_empno UNIQUE (department_id, employee_no)            # department_id + employee_no 这个组合不能重复
    );
    ```

4. 查看表的约束

    ```sql
    SELECT * FROM information_schema.table_constraints WHERE table_name = '表名';
    
    # 查看索引，唯一性约束、主键约束、外键约束都能看
    SHOW INDEX FROM 表名;
    ```

5. 建表后`ALTER TABLE`增加唯一性约束

    ```sql
    ALTER TABLE 表名
    ADD [CONSTRAINT 约束名] UNIQUE (字段名);
    ```

    ```sql
    # 添加唯一性约束
    ALTER TABLE user
    ADD [CONSTRAINT uk_user_username] UNIQUE (username);
    
    ALTER TABLE user
    MODIFY COLUMN name VARCHAR(100) UNIQUE;
    
    # 添加联合唯一性约束
    ALTER TABLE user
    ADD CONSTRAINT uk_user_name_email
    UNIQUE (username, email);
    ```

6. 修改唯一性约束 `RENAME INDEX`

    唯一性只能直接改名，不能修改字段名；如需修改字段名，需要先删除旧的唯一性约束，再添加新的

    ```sql
    ALTER TABLE user
    RENAME INDEX uk_user_username TO uk_user_name;
    ```

7. 删除唯一性约束

    `MySQL` 中 `UNIQUE` 约束实际上会对应一个**唯一索引**。`MySQL` 的 `UNIQUE` 约束 ≈ 一个唯一索引，所以删除时 `DROP INDEX`。

    ```sql
    ALTER TABLE 表名
    DROP INDEX 约束名;
    ```

    ```sql
    ALTER TABLE user
    DROP INDEX uk_user_username;
    ```




## 3.`PRIMARY KEY` 主键约束

用来唯一标识表中的一行记录

要求：

- 相当于唯一性约束 + 非空约束（唯一且非空）
- 不能为 `NULL`
- 一张表通常只有一个主键约束
- 系统默认会在所在的列或列组合上建立对应的**主键索引**，所以使用主键查询效率会更高。如果删除主键约束了，主键约束对应的索引就自动删除了



1. 查看表索引

    ```sql
    # 查看索引，唯一性约束、主键约束、外键约束都能看
    SHOW INDEX FROM 表名;
    ```

2. 建表时`CREATE TABLE`标明主键

    ```sql
    # 列级约束
    CREATE TABLE user (
        id BIGINT PRIMARY KEY,        # 主键约束
        name VARCHAR(50) NOT NULL
    );
    
    # 表级约束
    CREATE TABLE user (
        id BIGINT,
        name VARCHAR(100),
        [CONSTRAINT 约束名] PRIMARY KEY (id)              # 主键约束，主键约束名字一般带 pk
    );
    ```

3. 建表后`ALTER TABLE`增加主键约束

    `Mysql` 的主键名总是 `PRIMARY`，自己命名也没用，所以能省则省

    ```sql
    ALTER TABLE user
    ADD CONSTRAINT pk_user PRIMARY KEY (id);
    
    # 省略 CONSTRAINT 约束名
    ALTER TABLE user
    ADD PRIMARY KEY (id);
    ```

4. 删除主键约束，开发中一般不删除主键约束

    ```sql
    # 主键只有一个，所以不用指定主键名
    ALTER TABLE user
    DROP PRIMARY KEY;
    ```

5. 联合主键，少用

    ```sql
    CREATE TABLE student_course (
        student_id BIGINT,
        course_id BIGINT,
        score INT,
        PRIMARY KEY (student_id, course_id)
    );
    ```



## 4.`AUTO INCREMENT` 自增列

- 一个表最多只能有一个自增长列
- 自增长列约束的列必须是键列（主键列，唯一键列）
- 自增约束的列的数据类型必须是整数类型

1. `CREATE TABLE` 添加自增列

    ```sql
    CREATE TABLE user (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        name VARCHAR(100)
    );
    
    # 插入数据时，不需要自己填写 id，数据库会自动生成
    INSERT INTO user (name)
    VALUES ('张三');
    # 就算插入时填了自增id，id还是会按照顺序自增，我们填入的值是没用的
    ```

    自增的值默认从1开始

    ```sql
    # 修改自增列的起始值
    ALTER TABLE user AUTO_INCREMENT = 1000;
    ```

2. `ALTER TABLE` 添加自增列

    ```sql
    ALTER TABLE user
    MODIFY COLUMN id BIGINT AUTO_INCREMENT;
    ```

3. 删除自增列

    自增值不会因为删除最后一条数据而“回收”

    ```sql
    ALTER TABLE user
    MODIFY COLUMN id BIGINT;
    ```



## 5.`FOREIGN KEY` 外键约束

限定某个表的某个字段的**引用完整性**：员工表的员工所在部门的选择，必须在部门表能找到对应的部分

开发中：不得使用外键与级联，**一切外键概念必须在应用层解决**

- （概念解释）学生表中的 student_id 是主键，那么成绩表中的 student_id 则为外键。如果更新学生表中的 student_id，同时触发成绩表中的 student_id 更新，即为级联更新。
- 外键与级联更新适用于 单机低并发 ，不适合 分布式 、 高并发集群 ；级联更新是强阻塞，存在数据库 更新风暴 的风险；
- 外键影响数据库的 插入速度 。



### 外键的“父表（主表）”和“子表（从表）”

主表（父表）：被引用的表，被参考的表

从表（子表）：引用别人的表，参考别人的表

例如：员工表的员工所在部门这个字段的值要参考部门表：部门表是主表，员工表是从表。



### 外键约束

1. 从表的外键列，必须引用/参考主表的**主键或唯一约束**的列
2. 创建(CREATE)表时就指定外键约束的话，**先创建主表**，再创建从表
3. 删表时，**先删从表**（或先删除外键约束），再删除主表
4. 在创建外键约束时，如果不给外键约束命名，**默认名不是列名，而是自动产生一个外键名**
5. 当主表的记录被从表参照时，**主表的记录将不允许删除**，如果要删除数据，需要先删除从表中依赖该记录的数据，然后才可以删除主表的数据
6. 在“从表”中指定外键约束，并且一个表可以建立多个外键约束
7. 从表的外键列与主表被参照的列名字可以不相同，但是**数据类型必须一样**，逻辑意义一致
8. **当创建外键约束时，系统默认会在所在的列上建立对应的普通索引**。但是索引名是外键的约束名。（根据外键查询效率很高）
9. 删除外键约束后，必须 手动 删除对应的索引



### 外键操作

1. 创建外键

    ```sql
    # 主表
    CREATE TABLE user (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        name VARCHAR(100)
    );
    
    # 从表和外键
    CREATE TABLE orders (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        user_id BIGINT,
    
        CONSTRAINT fk_order_user        # 外键约束名字一般带 fk
            FOREIGN KEY (user_id)       # 本表的 user_id
            REFERENCES user(id)         # user 表的 id
    );
    ```

2. 给已有表添加外键

    ```sql
    ALTER TABLE orders
    ADD CONSTRAINT fk_order_user
    FOREIGN KEY (user_id)
    REFERENCES user(id);
    ```

3. 删除外键

    ```sql
    # 查看索引，唯一性约束、主键约束、外键约束都能看
    SHOW INDEX FROM 表名;
    ```

    ```sql
    # 1.删除外键
    ALTER TABLE orders
    DROP FOREIGN KEY fk_order_user;
    
    # 2.手动删除对应的索引
    ALTER TABLE orders
    DROP INDEX fk_order_user;
    ```



### `ON DELETE`

我们可以指定删除父记录时怎么办

1. `RESTRICT`：默认值，拒绝删除

2. `CASCADE`：父表删除，子表相关数据也一起删除，该操作要谨慎

    ```sql
    CREATE TABLE orders (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        user_id BIGINT,
    
        CONSTRAINT fk_order_user
            FOREIGN KEY (user_id)       # 本表的 user_id
            REFERENCES user(id)         # user 表的 id
        	ON DELETE CASCADE           # 主表删除的时候，从表也一起删除关联外键的记录
    );
    ```

3. `SET NULL`：主表删除的时候，从表置为 NULL（从表的该列不能设置 NOT NULL）

    ```sql
    CREATE TABLE orders (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        user_id BIGINT,
    
        CONSTRAINT fk_order_user
            FOREIGN KEY (user_id)       # 本表的 user_id
            REFERENCES user(id)         # user 表的 id
        	ON DELETE SET NULL          # 主表删除的时候，从表置为 NULL（从表的该列不能设置 NOT NULL）
    );
    ```



### `ON UPDATE`

1. `CASCADE`：主表更新的时候从表一起更新

    ```sql
    CREATE TABLE orders (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        user_id BIGINT,
    
        CONSTRAINT fk_order_user
            FOREIGN KEY (user_id)       # 本表的 user_id
            REFERENCES user(id)         # user 表的 id
        	ON UPDATE CASCADE           # 主表更新的时候从表一起更新
        	ON DELETE SET NULL          # 主表删除的时候，从表置为 NULL（从表的该列不能设置 NOT NULL）
    );
    ```





## 6.`CHECK` 检查约束

`MySQL 5.7` 不支持检查约束，`MySQL 8.0` 后支持了

给数据库加一个“数据合法性检查”

1. 创建检查约束

    ```sql
    CREATE TABLE employees (
        id BIGINT PRIMARY KEY,
        name VARCHAR(100),
        age INT CHECK (age >= 0 AND age <= 150)
    );
    
    # 表级别约束
    CREATE TABLE employees (
        id BIGINT PRIMARY KEY,
        name VARCHAR(100),
        age INT,
    
        CONSTRAINT chk_employee_age         # chk
            CHECK (age >= 0 AND age <= 150)
    );
    ```

2. 已有的表添加检查约束

    ```sql
    ALTER TABLE employees
    ADD CONSTRAINT chk_employee_age
    CHECK (age >= 18);
    ```

3. 删除检查约束

    ```sql
    ALTER TABLE employees
    DROP CHECK chk_employee_age;            # 根据约束名删除
    ```

    



## 7.`DEFAULT` 默认值约束

插入数据时，如果没有给某个字段提供值，就自动使用指定的默认值

1. 创建默认值约束

    ```sql
    CREATE TABLE user (
        id BIGINT PRIMARY KEY AUTO_INCREMENT,
        name VARCHAR(100),
        age INT DEFAULT 18,
        status VARCHAR(20) DEFAULT 'active',
        create_time DATETIME DEFAULT CURRENT_TIMESTAMP
    );
    ```

    显式提供 NULL

    ```sql
    # 如果想一直使用默认值，可以给列加上 NOT NULL
    INSERT INTO user (age)
    VALUES (NULL);            # 将不会使用默认值 18
    ```

2. 修改 `DEFAULT`

    ```sql
    ALTER TABLE user
    MODIFY COLUMN status VARCHAR(20) DEFAULT 'inactive';
    ```

3. 删除 `DEFAULT`

    ```sql
    # 如果原字段有其他属性，不能随便漏掉
    ALTER TABLE user
    MODIFY COLUMN status VARCHAR(20);
    ```

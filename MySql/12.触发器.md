# 触发器

`MySQL 5.0.2` 版本开始支持

触发器：当表发生某种指定操作（包括 `INSERT`、`UPDATE`、`DELETE` 事件）时，数据库自动执行的一段 `SQL`。它最大的特点就是 **自动触发**，不需要你在业务代码里手动调用

优点：

1. 触发器可以确保数据的完整性。操作1自动触发操作2，更新另一个表
2. 触发器可以帮助记录日志
3. 触发器可以在操作数据前，对数据进行合法性检查

缺点：

1. 触发器最大的问题就是可读性差，不受应用层的控制
2. 相关数据的变更，可能会导致触发器出错，难以排查



## 创建触发器

```sql
CREATE TRIGGER 触发器名称
触发时机 触发事件           # 触发时机有 BEFORE | AFTER，触发事件有 INSERT | UPDATE | DELETE；一共 2 * 3 = 6 种组合
ON 表名
FOR EACH ROW              # 每影响一行数据，就触发一次
BEGIN
    SQL语句;
END;
```

```sql
CREATE TRIGGER user_after_update
AFTER UPDATE
ON user_info
FOR EACH ROW
BEGIN
    INSERT INTO user_log(user_id, operation_note)
    VALUES (NEW.id, '修改用户');
END;
```



### `NEW` 和 `OLD`

| 操作     | `OLD`        | `NEW`      |
| -------- | ------------ | ---------- |
| `INSERT` | ❌            | 新数据     |
| `UPDATE` | 修改前数据   | 修改后数据 |
| `DELETE` | 被删除的数据 | ❌          |



### 校验数据，利用 `SIGNAL` 主动抛错

```sql
# 员工的工资大于领导的工资，使用 BEFORE，直接抛出错误，致使插入失败
DELIMITER //

CREATE TRIGGER salary_check_trigger
BEFORE INSERT
ON employees
FOR EACH ROW
BEGIN
	DECLARE mgrsalary DOUBLE;
	SELECT salary INTO mgrsalary FROM employees WHERE employee_id = NEW.manager_id;

	IF NEW.salary > mgrsalary THEN
		SIGNAL SQLSTATE 'HY000' SET MESSAGE_TEXT = '薪资高于领导薪资错误';
	END IF;
END //

DELIMITER ;
```



## 查看触发器

```sql
SHOW TRIGGERS;

SHOW TRIGGERS\G;

# 查看数据库的触发器
SHOW TRIGGERS FROM 数据库名;

# 查看具体触发器
SHOW CREATE TRIGGER 触发器名;

# 从 `information_schema.TRIGGERS` 库表中查询触发器
SELECT * FROM information_schema.TRIGGERS;
```



## 删除触发器

```sql
DROP TRIGGER 触发器名;

DROP TRIGGER IF EXISTS 触发器名;
```

# 多表查询

开发规范：考虑到性能问题，**超过三个表禁止使用`JOIN`**。如果三张表都有10000条数据，并且关联字段都没有索引，在最坏情况下可能产生 10000 * 10000 * 10000 = 10000亿 级别的行比较；恭喜你，数据库爆了

> 如果表比较大，关联字段记得建立索引

替代 `JOIN` 的方案

1. **增加冗余数据**：比如查询订单的用户名，直接在 订单表 增加除 `user_id` 外的 `user_name` 冗余字段
2. **应用层处理**：先在订单表查询出 `user_id`，再使用 `IN (user_id)` 去用户表批查询用户名，`user_id` 一般带有主键索引，查询速度也不错。这样就跳过了全表 `JOIN`

|               | `JOIN` | 数据冗余       | 应用层关联 |
| ------------- | ------ | -------------- | ---------- |
| 查询性能      | 很快   | 最快           | 快         |
| 分库分表      | 受限制 | 支持           | 支持       |
| 数据一致性    | 强     | :warning: 风险 | 强         |
| `SQL` 次数    | 1次    | 1次            | 2次        |
| 开发复杂度    | 低     | 高             | 低         |
| 存储/维护成本 | 低     | 高             | 低         |
| 推荐性        | ⭐⭐⭐⭐⭐  | ⭐⭐⭐⭐           | ⭐⭐⭐⭐       |



## 内连接（两表的交集）

以后直接使用 `SQL99` 的语法就行

```sql
# SQL92 语法；隐式内连接
SELECT *
FROM TableA, TableB
WHERE TableA.id = TableB.id;

# SQL99 语法用 JOIN ... ON ...；显示内连接（INNER 可以省略）
SELECT *
FROM TableA
INNER JOIN TableB
ON TableA.id = TableB.id;
```

多表连接（TableA, TableB, TableC）

```sql
SELECT *
FROM TableA, TableB, TableC
WHERE TableA.id = TableB.id
AND TableB.name = TableC.name;

SELECT *
FROM TableA
INNER JOIN TableB
ON TableA.id = TableB.id
JOIN TableC
ON TableB.name = TableC.name;
```

自连接

```sql
SELECT A.id, B.name
FROM TableA A, TableB B
WHERE A.id = B.id;
```



## 左外连接（左表全保留，右表不匹配的字段返回`Null`）

```sql
# SQL99语法才有，OUTER可以省略
SELECT *
FROM TableA
LEFT OUTER JOIN TableB
ON TableA.id = TableB.id;
```



## 右外连接（右表全保留，左表不匹配的字段返回`Null`）

```sql
# # SQL99语法才有，OUTER可以省略
SELECT *
FROM TableA
RIGHT OUTER JOIN TableB ON TableA.id = TableB.id;
```



## 满外连接

`MySql` 用（`MySql` 不支持 `FULL OUTER JOIN`）

```sql
SELECT *
FROM TableA
LEFT JOIN TableB
ON TableA.id = TableB.id

# UNION ALL      # 不去重
UNION          # 去重，由于是在 UNION ALL 的基础上去重，所以效率会比较低

SELECT *
FROM TableA
RIGHT JOIN TableB
ON TableA.id = TableB.id;
```

```sql
# UNION ALL 效率高的写法
SELECT *
FROM TableA
LEFT JOIN TableB
ON TableA.id = TableB.id
UNION ALL      # 不去重
SELECT *
FROM TableA
RIGHT JOIN TableB
ON TableA.id = TableB.id
WHERE TableA.id IS NULL;
# WHERE 最好放第个JOIN，这样最终的表顺序与 UNION 才对的上
```

`Oracle` 用

```sql
SELECT *
FROM TableA
FULL OUTER JOIN TableB
ON TableA.id = TableB.a_id;
```

### 注意

1. 如果查询语句中出现了多个表中都存在的字段，则必须指明此字段所在的表

    ```sql
    SELECT TableA.a, TableB.a
    FROM TableA
    INNER JOIN TableB
    ON TableA.id = TableB.id;
    
    # 简化写法也可以使用表别名
    # 如果给表起了别名，一旦在SELECT或WHERE中使用表名的话，则必须使用表的别名，而不能再使用表的原名
    SELECT A.a, B.a
    FROM TableA A
    INNER JOIN TableB B
    ON A.id = B.id;
    ```




## 自然连接

一般不用，不好控制，我的开发中禁止使用

**自动查询两张连接表中所有相同的字段，然后进行 等值连接；**比如两个表都有`id`、`name`字段，它会自动按照这两个字段相等做连接

```sql
# 写法
SELECT *
FROM TableA
NATURAL JOIN TableB;
```

如果两表没有相同字段，相当于

```sql
SELECT *
FROM TableA
JOIN TableB
ON 1 = 1;
```



## USING

省略连接条件，简写而已

```SQL
# 按照 id 相等连接
SELECT *
FROM TableA
JOIN TableB
USING (id);
```

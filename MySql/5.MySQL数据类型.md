# MySQL中的数据类型

| 分类                              | 数据类型                                                     |
| --------------------------------- | ------------------------------------------------------------ |
| 整数类型（Integer）               | TINYINT、SMALLINT、MEDIUMINT、**`INT(INTEGER)`**、`BIGINT`   |
| 浮点数类型（Floating-Point）      | `FLOAT`、`DOUBLE`                                            |
| 定点数类型（Fixed-Point）         | **`DECIMAL`**、NUMERIC（DECIMAL 的同义词）                   |
| 位类型（Bit）                     | BIT                                                          |
| 日期时间类型（Date & Time）       | `YEAR`、`TIME`、**`DATE`**、`DATETIME`、`TIMESTAMP`          |
| 文本字符串类型（String）          | `CHAR`、**`VARCHAR`**、TINYTEXT、`TEXT`、MEDIUMTEXT、LONGTEXT |

| 集合类型（Set）                   | SET                                                          |

| 空间数据类型（Spatial）           | 单值：GEOMETRY、POINT、LINESTRING、POLYGON；<br />集合：MULTIPOINT、MULTILINESTRING、MULTIPOLYGON、GEOMETRYCOLLECTION |

开发规范：

- 任何字段如果为非负数，必须是 `UNSIGNED`

## 2.浮点数类型

浮点数加不加 `UNSIGNED` 没有区别，所以不用加了

| 类型              | 字节       | 大致取值范围                  | 有效数字                                        | 说明                                                         |
| :---------------- | :--------- | :---------------------------- | :---------------------------------------------- | ------------------------------------------------------------ |
| `FLOAT`           | 4（32bit） | ±3.4028 × 10³⁸（$2^{128}$）   | ~7 位（$2^{23} = 8388608$，7位数）              | 无需使用`UNSIGNED`<br />适用于近似值计算，不建议用于金额<br />MySQL 8.0 中 `M,D` 已不推荐使用 |
| `DOUBLE` / `REAL` | 8（64bit） | ±1.7977 × 10³⁰⁸（$2^{1024}$） | ~15～16 位（$2^{52} = 4503599627370496$，16位） | 无需使用`UNSIGNED`<br />适用于近似值计算，不建议用于金额<br />MySQL 8.0 中 `M,D` 已不推荐使用 |

```sql
SELECT CAST(0.1 AS DOUBLE) + CAST(0.2 AS DOUBLE);        # 结果并不是 0.3，所以浮点数并不适用于金额
```

`FLOAT` 存储（IEEE 754）

| 符号（S） | 阶码（E） | 尾数（M） |
| --------- | --------- | --------- |
| 1bit      | 8bit      | 23bit     |

`DOUBLE` 存储（IEEE 754）

| 符号（S） | 阶码（E） | 尾数（M） |
| --------- | --------- | --------- |
| 1bit      | 11bit     | 52bit     |



## 3.定点数类型

开发规范：

- 小数类型为 `DECIMAL`，禁止使用 `FLOAT` 和 `DOUBLE`，因为精度问题
- 如果存储的数据范围超过 `DECIMAL` 的范围，建议将数据拆成整数和小数并分开存储

| 类型                                   | 字节                                                    | 取值范围                                            | 近似精度         | 说明                                                         |
| :------------------------------------- | :------------------------------------------------------ | :-------------------------------------------------- | :--------------- | ------------------------------------------------------------ |
| `DECIMAL(M, D)`<br />`DEC` / `NUMERIC` | 每 9 位十进制数字 ≈ 4 字节<br />不足 9 位按位数分组计算 | M 最大为 65<br />D 最大为 30<br />`DECIMAL(65, 30)` | 精确到指定小数位 | **定点数**，非浮点数，但常一起比较。可精确存储，适合金额等财务数据 |

```sql
DECIMAL(10, 2)            # 总共最多 10 位数字，其中 2 位是小数；如 12345678.90

# 12345678.456 -> 12345678.46
```

如果存储的小数位超过D，那么会按照四舍五入的D位存储



存储方式：

> `DECIMAL(M,D)` 是定点数，采用十进制精确数值表示，小数点位置固定为 `D` 位，因此不会产生 `FLOAT/DOUBLE` 那种二进制浮点精度误差。
>
> ```sql
> 对于 12345678.90
> 12345678 | 90
> 整数部分   小数部分
> ```
>
> MySQL 内部会采用**二进制字节来存储这些十进制数字组**，但它保持的是**十进制精度语义**

## 5.日期与时间类型

| 类型           | 格式                  | 范围                                                  | 占用空间 | 精度 | 说明                                                         |
| -------------- | --------------------- | ----------------------------------------------------- | -------- | ---- | ------------------------------------------------------------ |
| `YEAR`         | `YYYY`                | `1901` ~ `2155`                                       | 1 字节   | 年   | 只存年份                                                     |
| `DATE`         | `YYYY-MM-DD`          | `1000-01-01` ~ `9999-12-31`                           | 3 字节   | 天   | 只存日期，不存时间                                           |
| `TIME`         | `HH:MM:SS`            | `-838:59:59` ~ `838:59:59`                            | 3 字节   | 秒   | 存储时间/时间间隔，可为负数                                  |
| **`DATETIME`** | `YYYY-MM-DD HH:MM:SS` | `1000-01-01 00:00:00` ~ `9999-12-31 23:59:59`         | 5 字节   | 秒   | 日期 + 时间，不受时区影响；开发中用这个                      |
| `TIMESTAMP`    | `YYYY-MM-DD HH:MM:SS` | `1970-01-01 00:00:01` UTC ~ `2038-01-19 03:14:07` UTC | 4 字节   | 秒   | **日期 + 时间**，按 UTC 存储，查询时按会话时区转换<br />这个并不是时间戳，时间戳应该使用 `BIGINT` 存储 |

```SQL
CREATE TABLE IF NOT EXISTS test_date(
	`year` YEAR,
	`date` DATE,
	`time` TIME,
	dt DATETIME,
	utc_dt TIMESTAMP,
	`timestamp` BIGINT
);

DESC test_date;

SELECT * FROM test_date;

INSERT INTO test_date (`year`, `date`, `time`, dt, utc_dt, `timestamp`)
VALUES
	(YEAR(CURDATE()), CURDATE(), CURTIME(), NOW(), NOW(), UNIX_TIMESTAMP()),
	('2026', '2026-08-10', '14:00:00', '2026-08-10 14:00:00', '2026-08-10 14:00:00', 1786348185);   # 字符串会隐式转换

# 查看时区
SELECT @@session.time_zone;
# 设置时区
SET time_zone = '+08:00';
# 设置成系统时区
SET SESSION time_zone = 'SYSTEM';
```



## 6.文本字符串类型

| 类型         | 长度           | 长度范围                  | 占用空间                       | 说明                                                         |
| ------------ | -------------- | ------------------------- | ------------------------------ | ------------------------------------------------------------ |
| `CHAR(M)`    | `M` 个字符     | `0 ~ 255`字符             | `M × 字符集最大字节数`         | **定长字符串**；不指定长度默认是1字符                        |
| `VARCHAR(M)` | `M` 个**字符** | `0 ~ 65,535`**字节**      | 实际字符串长度 + 1～2 **字节** | **变长字符串**；**定义时必须指定长度**，不然会报错<br />`VARCHAR` 是变长的，开发中M定义多少一般是视**业务需求**定的<br />比如手机号可以是 `VARCHAR(20)`<br />如果存储汉字，汉字占 3 个字节，`utf8mb4`占4字节<br />最大字符长度是 65535 / 3 = 21845 |
| `TINYTEXT`   | —              | 最大 `255` 字节           | 实际长度 + 1 字节              | 小型文本                                                     |
| `TEXT`       | —              | 最大 `65,535` 字节        | 实际长度 + 2 字节              | 普通文本                                                     |
| `MEDIUMTEXT` | —              | 最大 `16,777,215` 字节    | 实际长度 + 3 字节              | 中型文本                                                     |
| `LONGTEXT`   | —              | 最大 `4,294,967,295` 字节 | 实际长度 + 4 字节              | 超大型文本                                                   |

---

`CHAR(M)`：定长字符串；`CHAR(10)`表示最多存储10个字符，当存储的字符长度不足时候，会在字符的右边自动填充空格，'abc' -> 'abc       '。查询的时候会自动删除空格，所以存储的时候，字符串右边的空格会被自动忽略

| 类型         | 特点         | 空间上                 | 性能上                 | 适用场景                                                     |
| ------------ | ------------ | ---------------------- | ---------------------- | ------------------------------------------------------------ |
| `CHAR(M)`    | **固定长度** | 长度固定，可能浪费空间 | 长度固定，处理相对简单 | 长度固定或者足够短，速度要求高<br />定长的uuid，身份证号，门牌号（一般是3-4位数）等 |
| `VARCHAR(M)` | **可变长度** | **节省存储空间**       | 效率低                 | 长度变化较大的普通字符串                                     |

从存储引擎来讲

1. `InnoDB`引擎：建议使用 `VARCHAR`，定长简短的使用 `CHAR`
2. `MyISAM`引擎：定长建议使用 `CHAR`
3. `MEMORY`引擎：`VARCHAR` = `CHAR`，所以使用谁都没关系，统一使用 `VARCHAR` 吧

---

`TEXT` 没什么好讲的，如果是较大的文本，使用 `VARCHAR` 可能不太合适，就用 `TEXT` 就行，个人建议，超过 100 个字符的就直接用 `TEXT` 吧，也有建议是1000字符。开发的时候看场景的吧

`TEXT` 属于大文本类型，不能直接作为主键或建立完整字段索引，**MySQL** **不允许** **TEXT** **类型的字段做主键**；主键一般使用 `CHAR` 或者 `VARCHAR`

还有一种情况：如果存储的文本较大，还是要分表的，不然查询效率会比较低。超过1000字符就分表吧。



## 7.`ENUM` 类型

| 类型   | 长度/成元数  | 长度范围         | 占用的存储空间  | 说明                                                         |
| ------ | ------------ | ---------------- | --------------- | ------------------------------------------------------------ |
| `ENUM` | `L` 个枚举值 | `1 ≤ L ≤ 65,535` | `1` 或 `2` 字节 | **枚举字符串类型**，只能从预先定义的值中选择一个<br />枚举存储的不是字符串，而是存储给每个枚举值分配一个内部编号 |

```sql
CREATE TABLE IF NOT EXISTS test_enum(
	gender ENUM('0', '1', 'unknow')     # 没有限制非空的话，可以存储 NULL 值
);

INSERT INTO test_enum (gender)
VALUES ('0'), ('1');

SELECT * FROM test_enum;
```



## 8.`SET` 类型

在 `ENUM` 的基础上可以选择多个，8个成员以内存储空间一样，8个成员以上`SET`占的存储空间更大

| **文本字符串类型** | **长度/成员数** | **长度范围** | **占用的存储空间**                                           | **说明**                                               |
| ------------------ | --------------- | ------------ | ------------------------------------------------------------ | ------------------------------------------------------ |
| `SET`              | `L` 个集合成员  | `1 ≤ L ≤ 64` | `1～8` 字节<br />（$2^8 = 64$，每一位都代表该成员是否被选中） | **集合字符串类型**，可以从预先定义的值中选择一个或多个 |

```sql
CREATE TABLE user (
    name VARCHAR(50),
    hobby SET('篮球', '足球', '游泳', '跑步')
);

INSERT INTO user (name, hobby)
VALUES ('张三', '篮球');

INSERT INTO user (name, hobby)
VALUES ('王五', '篮球,足球,游泳');
```



## 9.二进制字符串类型

`MySQL` 中的二进制字符串类型主要存储一些二进制数据，比如可以存储**图片、音频和视频**等二进制数据

需要注意的是，在实际工作中，往往不会在MySQL数据库中使用BLOB类型存储大对象数据，通常会将图片、音频和视频文件存储到**服务器的磁盘**上，并将图片、音频和视频的**访问路径**存储到MySQL中。

| 类型           | 长度     | 长度范围                         | 占用空间             | 说明                 |
| -------------- | -------- | -------------------------------- | -------------------- | -------------------- |
| `BINARY(M)`    | `M` 字节 | `0 ≤ M ≤ 255`                    | `M` 字节             | **定长二进制字符串** |
| `VARBINARY(M)` | `M` 字节 | `0 ≤ M ≤ 65,535`                 | 实际长度 + 1～2 字节 | **变长二进制字符串** |
| `TINYBLOB`     | —        | 最大 `255` 字节                  | 实际长度 + 1 字节    | 小型二进制数据       |
| `BLOB`         | —        | 最大 `65,535` 字节（64KB）       | 实际长度 + 2 字节    | 普通二进制数据       |
| `MEDIUMBLOB`   | —        | 最大 `16,777,215` 字节（16MB）   | 实际长度 + 3 字节    | 中型二进制数据       |
| `LONGBLOB`     | —        | 最大 `4,294,967,295` 字节（4GB） | 实际长度 + 4 字节    | 大型二进制数据       |

```sql
CREATE TABLE IF NOT EXISTS test_blob(
	id INT,
	img MEDIUMBLOB
);

SELECT * FROM test_blob;

DESC test_blob;
```



## 10.`JSON` 类型

| 类型   | 长度 | 长度范围                       | 占用空间               | 说明                                                         |
| ------ | ---- | ------------------------------ | ---------------------- | ------------------------------------------------------------ |
| `JSON` | —    | 受 `max_allowed_packet` 等限制 | 根据实际 JSON 数据决定 | **JSON 文档类型**，支持对象、数组、字符串、数字、布尔值和 `null` |

```sql
CREATE TABLE test_json (
    id BIGINT PRIMARY KEY,
    info JSON
);

INSERT INTO test_json(id, info)
VALUES (
    1,
    '{"name":"张三","age":18}'
);

# 可以 `-> + $` 查询 JSON 中的 name；返回 json 值
SELECT info -> '$.name'
FROM test_json;
# 返回字符串
SELECT info ->> '$.name'
FROM test_json;
```



## 11.空间类型

MySQL 空间类型扩展支持地理特征的生成、存储和分析。这里的地理特征表示世界上具有位置的任何东西，可以是一个实体，例如一座山；可以是空间，例如一座办公楼；也可以是一个可定义的位置，例如一个十字路口等等。MySQL中使用 Geometry（几何） 来表示所有地理特征。Geometry指一个点或点的集合，代表世界上任何具有位置的事物。

| 类型                 | 含义         | 示例              |
| -------------------- | ------------ | ----------------- |
| `GEOMETRY`           | 任意几何对象 | 点、线、面等      |
| `POINT`              | 点           | `(116.40, 39.90)` |
| `LINESTRING`         | 线           | 多个点组成的线    |
| `POLYGON`            | 多边形       | 一个封闭区域      |
| `MULTIPOINT`         | 多个点       | 多个位置          |
| `MULTILINESTRING`    | 多条线       | 多条道路          |
| `MULTIPOLYGON`       | 多个多边形   | 多个区域          |
| `GEOMETRYCOLLECTION` | 几何对象集合 | 点、线、面混合    |

空间类型扩展很多，这里仅做了解，有遇到的话，得专门学。

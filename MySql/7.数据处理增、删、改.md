```sql
CREATE TABLE employee (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50),
    age INT,
    salary DECIMAL(10, 2)
);
```

基于该表操作



# `INSERT INTO` 插入

```sql
# 1.插入一条数据
INSERT INTO employee (name, age, salary)
VALUES ('张三', 25, 8000);

# 2.插入多条数据
INSERT INTO employee (name, age, salary)
VALUES
    ('张三', 25, 8000),
    ('李四', 30, 10000),
    ('王五', 28, 9000);

# 3.省略列名（不推荐）
INSERT INTO employee
VALUES (4, '赵六', 26, 7000);
```

> 不推荐使用省略列名的写法，它必须严格按照表中字段的顺序，而且以后表结构发生变化，这种 SQL 很容易出问题。

> 如果字段有 `NOT NULL` 等约束，需要按照约束插入，否则会插入失败

```sql
# 将查询结果插入到表中
INSERT INTO 目标表 (字段1, 字段2, 字段3)
SELECT 字段1, 字段2, 字段3
FROM 来源表
WHERE 条件;

# 需要注意两个表字段的类型是否相同
INSERT INTO employee_backup (id, name, age, salary)
SELECT id, name, age, salary          # 字段名字要一一对应
FROM employee;
```



# `UPDATE` 改

```sql
UPDATE 表名
SET 字段1 = 值1,
    字段2 = 值2
WHERE 条件;
```

在修改数据时，由于约束的影响，是可能导致修改失败的

1. 修改单个字段

   ```sql
   UPDATE employee
   SET salary = 9000
   WHERE id = 1;
   ```

2. 修改多个字段

   ```sql
   UPDATE employee
   SET age = 26, salary = 9500
   WHERE id = 1;
   ```

3. 根据条件批量修改

   ```sql
   UPDATE employee
   SET salary = salary + 1000
   WHERE age > 30;
   ```

4. UPDATE 最危险的地方：`WHERE`

   ```sql
   UPDATE employee
   SET salary = 9000;
   ```

   > 没有 `WHERE`，意味着：把 employee 表中所有员工的工资都改成 9000



# `DELETE` 删除

在删除数据时，也有可能因为约束的影响，导致删除失败（如删除的数据中有外键约束等）

```sql
DELETE FROM 表名
WHERE 条件;
```

```sql
DELETE FROM employee
WHERE id = 1;

DELETE FROM employee
WHERE age > 30;
```

`DELETE` 也有一个非常危险的地方

```sql
DELETE FROM employee;
```

> 没有 `WHERE`，意味着：删除 employee 表中的所有数据



# MySQL 8 新特性：计算列`Generated Column`

`GENERATED ALWAYS AS`，其中 `GENERATED ALWAYS` 可以不写

```sql
字段名 数据类型
GENERATED ALWAYS AS (表达式)
[VIRTUAL | STORED]
```

```sql
CREATE TABLE employee (
    name VARCHAR(50),
    birth_year INT,
    age INT GENERATED ALWAYS AS (YEAR(CURDATE()) - birth_year)
);

CREATE TABLE employee (
    name VARCHAR(50),
    birth_year INT,
    age INT AS (YEAR(CURDATE()) - birth_year)       # 省略 GENERATED ALWAYS
);
```

> 计算列不能直接 `INSERT`，也不能直接 `UPDATE` 计算列，当改动其他列时会自动计算



### `VIRTUAL` 虚拟生成列（默认值）

不真正把计算结果存储在磁盘中，查询的时候计算

```sql
CREATE TABLE employee (
    name VARCHAR(50),
    birth_year INT,
    age INT
    GENERATED ALWAYS AS (YEAR(CURDATE()) - birth_year)
    VIRTUAL
);
```



### `STORED` 存储生成列

```sql
CREATE TABLE employee (
    name VARCHAR(50),
    birth_year INT,
    age INT
    GENERATED ALWAYS AS (YEAR(CURDATE()) - birth_year)
    STORED
);
```

计算结果真正存储起来。



| 两者对比       | VIRTUAL                  | STORED   |
| -------------- | ------------------------ | -------- |
| 计算结果存储   | ❌                        | ✅        |
| 查询时计算     | ✅                        | ❌        |
| 占用存储空间   | 较少                     | 较多     |
| 写入时计算     | 不需要保存               | 需要计算 |
| 查询时计算成本 | 有                       | 无       |
| 可以建立索引   | MySQL 8 可以通过索引支持 | 可以     |

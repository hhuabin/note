# 存储过程 `PROCEDURE`

存储过程：`Stored Procedure`，就是一组经过 **预先编译** 的 SQL 语句的封装。可以通过 `CALL` 执行

优点：

1. **存储过程可以一次编译多次使用。**存储过程只在创建时进行编译，之后的使用都不需要重新编译，这就提升了 SQL 的执行效率。
2. **可以减少开发工作量。**将代码 封装 成模块，实际上是编程的核心思想之一，这样可以把复杂的问题拆解成不同的模块，然后模块之间可以 重复使用 ，在减少开发工作量的同时，还能保证代码的结构清晰。
3. **存储过程的安全性强。**我们在设定存储过程的时候可以 设置对用户的使用权限 ，这样就和视图一样具有较强的安全性
4. **可以减少网络传输量。**因为代码封装到存储过程中，每次使用只需要调用存储过程即可，这样就减少了网络传输量。
5. **良好的封装性。**在进行相对复杂的数据库操作时，原本需要使用一条一条的 SQL 语句，可能要连接多次数据库才能完成的操作，现在变成了一次存储过程，只需要 连接一次即可 。
6. 可以处理事务

缺点：【阿里强制】==**禁止使用存储过程**==，存储过程难以调试和扩展，更没有移植性。

1. **可移植性差。**存储过程不能跨数据库移植，比如在 MySQL、Oracle 和 SQL Server 里编写的存储过程，在换成其他数据库时都需要重新编写。

2. **调试困难。**只有少数 DBMS 支持存储过程的调试。对于复杂的存储过程来说，开发和维护都不容易。虽然也有一些第三方工具可以对存储过程进行调试，但要收费。

3. **存储过程的版本管理很困难。**比如数据表索引发生变化了，可能会导致存储过程失效。我们在开发软件的时候往往需要进行版本管理，但是存储过程本身没有版本控制，版本迭代更新的时候很麻烦。

4. **它不适合高并发的场景。**高并发的场景需要减少数据库的压力，有时数据库会采用分库分表的方式，而且对可扩展性要求很高，在这种情况下，存储过程会变得难以维护， 增加数据库的压力 ，显然就

    适用了。



## 查看存储过程

1. 查看存储过程

    ```sql
    SHOW PROCEDURE STATUS;
    
    # 模糊查询
    SHOW PROCEDURE STATUS LIKE '%select%';
    
    # 从 `information_schema.ROUTINES` 库表中查询
    SELECT * FROM information_schema.ROUTINES
    WHERE ROUTINE_NAME = '存储过程名'
    [AND ROUTINE_TYPE = {'PROCEDURE|FUNCTION'}];;
    ```

2. 查看指定数据库的存储过程

    ```sql
    SHOW PROCEDURE STATUS
    WHERE Db = 'test';
    ```

3. 查看具体定义

    ```sql
    SHOW CREATE PROCEDURE 存储过程名;
    
    SHOW CREATE PROCEDURE get_employee;
    
    # 命令行使用 \G
    SHOW CREATE PROCEDURE get_employee\G;
    ```




## 创建存储过程

```sql
CREATE PROCEDURE 过程名(
    IN | OUT | INOUT 参数名 参数类型
)
[特性声明]
BEGIN
    SQL语句;
END;
```

```sql
# 无输入无输出的存储过程
CREATE PROCEDURE get_employees()
BEGIN
    SELECT * FROM employees;
END;
```

存储过程参数有三种

1. `IN`：调用者把数据传给存储过程
2. `OUT`：存储过程执行完以后，把结果传出来
3. ``INOUT`：既可以传进去，又可以带结果出来

---

1. `IN`

    ```sql
    DELIMITER //
    
    CREATE PROCEDURE get_employee(
        IN emp_id INT      # IN 参数 类型最好和表中字段的类型一致
    )
    BEGIN
        SELECT *
        FROM employees
        WHERE id = emp_id;
    END //
    
    DELIMITER ;
    
    # 调用存储过程
    CALL get_employee(1001);
    ```

2. `OUT`

    ```sql
    DELIMITER //
    
    CREATE PROCEDURE get_employee_count(
        OUT total INT
    )
    BEGIN
        SELECT COUNT(*)
        INTO total
        FROM employees;
    END //
    
    DELIMITER ;
    ```

    ```sql
    # 调用
    CALL get_employee_count(@total);
    
    SELECT @total;
    ```

3. `INOUT`

    ```sql
    DELIMITER //
    
    CREATE PROCEDURE test(
        INOUT num INT
    )
    BEGIN
        SET num = num + 10;
    END //
    
    DELIMITER ;
    ```

    ```sql
    # 调用
    SET @num = 20;
    
    CALL test(@num);
    
    SELECT @num;
    ```




### `DELIMITER` 新的结束标记

MySQL 默认的语句结束符号为分号`;`。为了避免与存储过程中SQL语句结束符相冲突，需要使用 `DELIMITER` 临时修改结束符

比如可以把 `DELIMITER //` 或 `DELIMITER $` 临时修改结束符；修改后记得恢复 `;` 结束符

```sql
DELIMITER //

CREATE PROCEDURE test()
BEGIN
    SELECT 1;
    SELECT 2;
END //

# 恢复 ; 结束符
DELIMITER ;
```



## 调用存储过程

```sql
CALL 存储过程名();

CALL get_employees();
```



## 修改存储过程

只能修改存储函数的特性，不能修改函数体，一般不用

```sql
ALTER {PROCEDURE | FUNCTION} 存储过程或函数的名 [characteristic ...]
```



## 删除存储过程

```sql
DROP PROCEDURE 存储过程名;

DROP PROCEDURE IF EXISTS 存储过程名;
```





# 存储函数 `FUNCTION`

存储函数的核心是：输入 → 计算 → 返回**一个**值（只能返回一个值）

| 对比                       | 存储过程                   | 存储函数             |
| -------------------------- | -------------------------- | -------------------- |
| 创建                       | `CREATE PROCEDURE`         | `CREATE FUNCTION`    |
| 调用                       | `CALL xxx()`               | `SELECT xxx()`       |
| 是否必须返回值             | ❌ 不要求                   | ✅ 必须               |
| `RETURN`                   | 一般不用返回值             | ✅ 必须               |
| `OUT` 参数                 | ✅ 支持                     | ❌ 不支持             |
| `INOUT` 参数               | ✅ 支持                     | ❌ 不支持             |
| 能否直接用于 `SELECT` 语句 | ❌                          | ✅                    |
| 更适合                     | 执行一系列操作，更新数据库 | 计算并返回**一个值** |

使用方式：

```sql
存储过程
    ↓
我要你帮我“做事情”
    ↓
执行 update delete，修改数据库

存储函数
    ↓
我要你帮我“算一个值”
    ↓
查询操作，定义函数，返回一个值
```

## 创建存储函数

```sql
CREATE FUNCTION 函数名(参数)
RETURNS 返回类型
[特性声明]
BEGIN
    ...
    RETURN 返回值;
END;
```

```sql
DELIMITER //

CREATE FUNCTION add_num(
    a INT,
    b INT
)
RETURNS INT
BEGIN
    RETURN a + b;
END //

DELIMITER ;
```

```sql
# 使用查询语句
DELIMITER //

CREATE FUNCTION get_email_by_name()
RETURNS VARCHAR(25)
	DETERMINISTIC
	CONTAINS SQL
	READS SQL DATA
BEGIN
	RETURN (
		SELECT email FROM employees
		WHERE last_name = 'Abel'
	);
END //

DELIMITER ;
```

若是报错`you *might* want to use the less safe log_bin_trust_function_creators variable`

1. 解决方式1：加上必要的函数特性`[NOT] DETERMINISTIC`和`{CONTAINS SQL | NO SQL | READS SQL DATA | MODIFIES SQL DATA}`

2. 解决方式2：配置全局变量

    ```sql
    SET GLOBAL log_bin_trust_function_creators = 1;
    ```

# 特性声明

创建存储过程时指定的对存储过程的约束条件

```sql
LANGUAGE SQL
| [NOT] DETERMINISTIC
| { CONTAINS SQL | NO SQL | READS SQL DATA | MODIFIES SQL DATA }
| SQL SECURITY { DEFINER | INVOKER }
| COMMENT 'string'
```

- `LANGUAGE SQL`：说明存储过程执行体是由SQL语句组成的，当前系统支持的语言为SQL
- `DETERMINISTIC`：对于相同的输入参数，函数保证返回相同的结果
- `SQL` 特性
    - `CONTAINS SQL`：函数包含 SQL 语句，但不读取或修改数据库中的数据
    - `NO SQL`：函数不包含 SQL 语句
    - `READS SQL DATA`：函数会读取数据库中的数据，但不会修改这些数据
    - `MODIFIES SQL DATA`：函数会修改数据库中的数据
- `SQL SECURITY { DEFINER | INVOKER }`：执行当前存储过程的权限，即指明哪些用户能够执行当前存储过程
    - `DEFINER` 表示只有当前存储过程的创建者或者定义者才能执行当前存储过程
    - `INVOKER` 表示拥有当前存储过程的访问权限的用户能够执行当前存储过程
- `COMMENT 'string'`：注释信息，可以用来描述存储过程。

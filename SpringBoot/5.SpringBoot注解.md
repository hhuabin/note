## `1.1` `@AliasFor` 别名注解

[AliasFor 官方文档](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/core/annotation/AliasFor.html)

`@AliasFor` 是 `Spring Framework` 提供的注解，主要用于声明注解属性之间的别名关系，常见于 `Spring` 的组合注解

-   当注解的参数名是 `value` 的时候，可以省略不写，所以一般都会配一个 `value` 参数当默认值

```java
// AliasFor 源码
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.METHOD})
@Documented
public @interface AliasFor {
    // @AliasFor 的 value 属性，是 attribute 属性的别名
    @AliasFor("attribute")
    String value() default "";

    // @AliasFor 的 attribute 属性，是 value 属性的别名
    @AliasFor("value")
    String attribute() default "";

    Class<? extends Annotation> annotation() default Annotation.class;
}
```

-   `value` 和 `attribute` 两个属性互为别名；即 `@AliasFor("path")` = `@AliasFor(attribute = "path")`

---

>   使用例子：**互为别名**
>
>   ```java
>   @Target(ElementType.METHOD)
>   @Retention(RetentionPolicy.RUNTIME)
>   @Documented
>   public @interface MyAnnotation {
>   
>       @AliasFor("name")
>       String value() default "";
>   
>       @AliasFor("value")
>       String name() default "";
>   }
>   ```
>
>   ```java
>   public class UserService {
>   
>       // value 和 name 是别名
>       @MyAnnotation("新增用户")
>       public void save() {
>       }
>   
>       // 等价于 @MyAnnotation("查询用户")
>       @MyAnnotation(name = "查询用户")
>       public void query() {
>       }
>   }
>   ```
>
>   不能取单向别名
>
>   ```java
>   /**
>    * 这是不完整的别名声明，在 Spring 的注解别名机制下不能正常使用
>    * @AliasFor("name") 默认表示：username 是 name 的别名，但注解中根本没有定义 name 属性
>    */
>   public @interface MyAnnotation {
>       @AliasFor("name")
>       String username() default "";
>   }
>   
>   // 正常人 一般会这样写，不需要 @AliasFor
>   public @interface MyAnnotation {
>       String name() default "";
>   }
>   ```



## `1.2` `@Configuration` 配置类注解

`@Configuration` 是 `Spring` 框架中用于**定义配置类**的核心注解，它本质上是一个**被 `@Component` 元注解标记的组件**，所以配置类本身也会被注册为 `Bean`

但它的关键价值不在于"是个 `Bean`"，而在于 **`Spring` 会对它做 `CGLIB` 代理增强**，从而保证配置类内部 `@Bean` 方法之间的调用仍然保持**单例语义**

1.   `@Configuration` 源码

     ```java
     // 源码
     @Target({ElementType.TYPE})
     @Retention(RetentionPolicy.RUNTIME)
     @Documented
     @Component           // @Configuration 本身就是一个 @Component
     public @interface Configuration {
         // 指定 Bean 名称，如 @Configuration("myConfig")
         @AliasFor(
             annotation = Component.class
         )
         String value() default "";
     
         // 默认开启 CGLIB 代理，保证 @Bean 方法间调用保持单例
         boolean proxyBeanMethods() default true;
     }
     ```

2.   `@Configuration` 使用

     ```java
     // 使用
     @Configuration          // 不指定名称的话，默认名称为 appConfig（类名首字母小写）
     public class AppConfig {
         
         @Bean
         public UserService userService() {
             return new UserServiceImpl();
         }
     }
     ```

-   告诉 `Spring` 这是一个配置类，`Spring` 容器启动时会加载它
-   类中被 `@Bean` 标注的方法，其返回值会注册为 `Spring` 容器中的 `Bean`
-   本质上是对 `XML` 中 `<beans>` 标签的替代

>   相关注解对比
>
>   | 注解                                     | 是否被代理 | 说明                                      |
>   | :--------------------------------------- | :--------- | :---------------------------------------- |
>   | `@Configuration`                         | 是（默认） | 完整配置类，方法间调用保持单例            |
>   | `@Configuration(proxyBeanMethods=false)` | 否         | 轻量配置类                                |
>   | `@Component`                             | 否         | 普通组件，即使有 `@Bean` 方法也不会被代理 |
>   | `@ComponentScan`                         | -          | 常与 `@Configuration` 搭配，扫描组件      |
>



## `1.3` `@Import` 导入注解

`@Import` 是 `Spring` 框架中一个非常核心的注解，主要用于**将指定的类（通常是配置类或普通组件）导入到当前 `Spring` 容器中**，使其成为 `Bean` 定义

它最常见的用途是**模块化配置**——你写了一个配置类，想让它在多个地方被复用，但又不想在每个主配置类里都手动写 `@Bean`，这时就可以用 `@Import` 把它“拉”进来

```java
// @Import 源码
@Target({ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface Import {
    Class<?>[] value();
}
```

`@Import` 的 `value` 可以接受三种类型的类：

1.   普通**配置类**（带 `@Configuration`）；直接导入，里面的 `@Bean` 会生效

     ```java
     @Configuration
     public class DatabaseConfig {
         @Bean
         public DataSource dataSource() {
             return new HikariDataSource();
         }
     }
     ```

     在 `MainConfig` 上导入：

     ```java
     @Configuration
     @Import(DatabaseConfig.class)
     public class MainConfig {
     }
     ```

2.   普通**组件类**（不带 `@Configuration`）

     即使类上没有 `@Configuration`，只要被 `@Import` 导入，它本身也会被注册为一个 Bean（相当于加了 `@Component`）

     默认组件的名字是 全类名

3.   `ImportSelector` 的实现类

     用于**动态批量导入**。实现 `selectImports` 方法，返回要导入的类名数组，`Spring` 会把这些类全部注册

     ```java
     public class MyImportSelector implements ImportSelector {
         @Override
         public String[] selectImports(AnnotationMetadata importingClassMetadata) {
             return new String[]{"com.example.A", "com.example.B"};
         }
     }
     ```

     ```java
     @Import(MyImportSelector.class)
     public class MainConfig {}
     ```

>   与 `@ComponentScan` 的区别
>
>   |                    | `@Import`                    | `@ComponentScan`             |
>   | :----------------- | :--------------------------- | :--------------------------- |
>   | 导入方式           | 显式指定类                   | 扫描包路径                   |
>   | 适用场景           | 精确导入、第三方类、动态导入 | 批量扫描自己项目里的组件     |
>   | 能否导入无注解的类 | 能（直接注册为 `Bean`）      | 不能（需要 `@Component` 等） |



## `1.4` `@Conditional` 条件装配注解

**根据特定条件决定是否注册某个 `Bean` 或某个配置类**，是实现"条件装配"的基石，也是 `Spring Boot` 自动配置（`@ConditionalOnXxx` 系列）的底层原理

| 注解                           | 作用                       |
| :----------------------------- | :------------------------- |
| `@ConditionalOnClass`          | `classpath` 中存在指定类   |
| `@ConditionalOnMissingClass`   | `classpath` 中不存在指定类 |
| `@ConditionalOnBean`           | 容器中存在指定 `Bean`      |
| `@ConditionalOnMissingBean`    | 容器中不存在指定 `Bean`    |
| `@ConditionalOnProperty`       | 配置项满足条件             |
| `@ConditionalOnResource`       | 存在指定资源文件           |
| `@ConditionalOnWebApplication` | 当前是 `Web` 应用          |



## `1.5` `@ImportResource` 导入 `XML` 配置注解

`@ImportResource` 是 `Spring` 框架中用于**导入 `XML` 配置文件**的注解，主要用于兼容老项目

如果说 `@Import` 是“导入 `Java` 配置类”，那么 `@ImportResource` 就是“导入 `XML` 配置文件”，两者互补，分别对应 `Spring` 的两种配置方式

1.   在 `resources` 目录下创建 `beans.xml`：

     ```xml
     <?xml version="1.0" encoding="UTF-8"?>
     <beans xmlns="http://www.springframework.org/schema/beans"
            xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
            xsi:schemaLocation="http://www.springframework.org/schema/beans
            http://www.springframework.org/schema/beans/spring-beans.xsd">
     
         <bean id="myService" class="com.example.MyService"/>
     </beans>
     ```

2.   **在配置类或启动类上添加注解**

     ```java
     @Configuration
     @ImportResource("classpath:beans.xml") // 加载 XML 配置文件，路径推荐使用 classpath: 前缀，避免路径解析问题
     public class AppConfig {
     }
     ```

     在 `Spring Boot` 中，通常直接标注在主启动类上



## `1.6` `@ConfigurationProperties` 配置属性绑定注解

`@ConfigurationProperties` 是 `Spring Boot` 中用于**将外部配置（`application.yml` / `application.properties`）批量、类型安全地绑定到 `Java Bean`** 的核心注解。它和 `@Value` 都能读配置，但定位完全不同：`@Value` 适合零散的单值注入，而 `@ConfigurationProperties` 适合**成组、有层次结构**的配置管理



### `1.6.1` 方式一：核心用法 `@Component` + `@ConfigurationProperties`

>   最常用

1.   配置文件（`application.yml`）

     ```yaml
     database:
       url: jdbc:mysql://localhost:3306/mydb
       username: root
       password: secret
     ```

2.   定义配置类并绑定前缀

     ```java
     @Component      // 注册为 Bean，只有容器中的组件才有用
     @ConfigurationProperties(prefix = "database") // 绑定 database.* 下的属性
     public class DatabaseProperties {
         private String url;
         private String username;
         private String password;
         // getter / setter 必须提供（Spring 通过 setter 注入）
     }
     ```

3.   使用

     ```java
     @Service
     public class MyService {
         @Autowired
         private DatabaseProperties dbProperties;
         // 直接使用 dbProperties.getUrl() 等
     }
     ```



### `1.6.2` 方式二：`@EnableConfigurationProperties`

在启动类或配置类上显式指定，适合不想给配置类加 `@Component` 的场景

1.   配置文件（`application.yml`）

     ```yaml
     database:
       url: jdbc:mysql://localhost:3306/mydb
       username: root
       password: secret
     ```

2.   定义配置类并绑定前缀

     ```java
     @ConfigurationProperties(prefix = "database") // 绑定 database.* 下的属性
     public class DatabaseProperties {
         private String url;
         private String username;
         private String password;
         // getter / setter 必须提供（Spring 通过 setter 注入）
     }
     ```

3.   在启动类或配置类上显式指定（如果第三包组件没有 `@Component` 就比较适合该方式）

     `@EnableConfigurationProperties`**会自动把 `DatabaseProperties` 注册到容器中，成为一个 Bean**

     ```java
     @EnableConfigurationProperties(DatabaseProperties.class)
     @SpringBootApplication
     public class App { }
     ```



### `1.6.3` 方式三：`@Bean` 方法上使用

适合绑定第三方类（你无法修改其源码）：

1.   配置文件（`application.yml`）

     ```yaml
     database:
       url: jdbc:mysql://localhost:3306/mydb
       username: root
       password: secret
     ```

2.   `DatabaseProperties` 类**不需要任何注解**（我们无法给第三方类添加任何注解，自然也就不会对它有要求）

     ```java
     public class DatabaseProperties {
         private String url;
         private String username;
         private String password;
         // getter / setter
     }
     ```

3.   `@Bean` 注册返回的实例

     ```java
     @Configuration
     public class DatabaseConfig {
     
         @Bean             // 被 @Configuration 注册为组件
         @ConfigurationProperties(prefix = "database")
         public DatabaseProperties databaseProperties() {
             return new DatabaseProperties();   // 手动 new 出实例
         }
     }
     ```

     -   `@Bean` 方法先**创建一个 `DatabaseProperties` 实例**，注册到容器
     -   方法上的 `@ConfigurationProperties(prefix = "database")` 告诉 `Spring`：**对这个 `Bean` 执行配置绑定**，把 `database.*` 的值注入进去
     -   最终容器里的 `DatabaseProperties` `Bean` 已经是**填充好配置**的实例



# 二、`SpringBoot` 自定义注解

自定义注解本身通常不负责实现功能，它只是一个“**标记**”或者“**配置**”。真正的业务逻辑由 `Spring` 的 `AOP`、拦截器、反射等机制来处理

                    自定义注解
                        │
        ┌───────────────┼───────────────┐
        ↓               ↓               ↓
       AOP            拦截器           反射
        │               │               │
     日志记录         权限校验        获取注解信息
     限流             登录验证
     防重复提交

| **组合方式**                                     | **主要用途**               | **典型场景**                               | **核心机制**                                 |
| ------------------------------------------------ | -------------------------- | ------------------------------------------ | -------------------------------------------- |
| **自定义注解 + `AOP`**                           | 日志、权限、限流等横切功能 | `@Log`、`@RequirePermission`、`@RateLimit` | 通过切面拦截带注解的方法                     |
| **自定义注解 + `HandlerInterceptor`**            | 请求拦截、登录校验等       | `@RequireLogin`                            | 在 `Controller` 方法执行前后拦截 `HTTP` 请求 |
| **自定义注解 + `HandlerMethodArgumentResolver`** | 自动解析并注入参数         | `@CurrentUser User user`                   | 根据参数上的注解自动解析参数值               |
| **自定义注解 + `Bean Validation`**               | 参数校验                   | `@Valid`、`@NotNull`、自定义校验注解       | 根据注解规则自动校验对象或参数               |



### `2.1` `AOP` 处理自定义注解

日志注解例子

1. 添加依赖

    ```xml
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-aop</artifactId>
    </dependency>
    ```

2. 定义自定义注解

    ```java
    @Target(ElementType.METHOD)
    @Retention(RetentionPolicy.RUNTIME)
    @Documented
    public @interface Log {
    
        String value() default "";
    }
    ```

3. 创建切面

    ```java
    @Aspect
    @Component
    public class LogAspect {
    
        @Around("@annotation(log)")  // 拦截所有使用了 @Log 注解的方法
        public Object around(
                ProceedingJoinPoint joinPoint,
                Log log
        ) throws Throwable {
    
            System.out.println("开始执行：" + log.value());
    
            long startTime = System.currentTimeMillis();
    
            Object result = joinPoint.proceed();
    
            long endTime = System.currentTimeMillis();
    
            System.out.println(
                    "执行完成，耗时：" +
                    (endTime - startTime) + "ms"
            );
    
            return result;
        }
    }
    ```

4. 使用

    ```java
    @RestController
    @RequestMapping("/user")
    public class UserController {
    
        @Log("查询用户")
        @GetMapping("/{id}")
        public User getUser(@PathVariable Long id) {
    
            return new User();
        }
    }
    ```




### `2.2` 拦截器(`Spring MVC` 拦截器)处理自定义注解

自定义注解 + `HandlerInterceptor` 实现 `token` 校验

1. 创建自定义注解

    ```java
    @Target(ElementType.METHOD)
    @Retention(RetentionPolicy.RUNTIME)
    public @interface RequireToken {
    }
    ```

2. 使用

    ```java
    @RestController
    @RequestMapping("/user")
    public class UserController {
    
        @RequireToken
        @GetMapping("/info")
        public String info() {
            return "用户信息";
        }
    }
    ```

3. 创建拦截器，拦截请求

    ```java
    @Component
    public class TokenInterceptor implements HandlerInterceptor {
    
        @Override
        public boolean preHandle(
                HttpServletRequest request,
                HttpServletResponse response,
                Object handler
        ) throws Exception {
    
            // 判断当前处理器是不是 Controller 方法
            if (!(handler instanceof HandlerMethod handlerMethod)) {
                return true;
            }
    
            // 获取方法上的 @RequireToken
            RequireToken requireToken = handlerMethod.getMethodAnnotation(RequireToken.class);
    
            // 没有 @RequireToken，不需要校验
            if (requireToken == null) {
                return true;
            }
    
            // 获取请求头中的 Token
            String token = request.getHeader("Authorization");
    
            // 校验 Token
            if (token == null || token.isEmpty()) {
                response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
                return false;
            }
    
            // TODO：实际项目中应该校验 Token 是否有效
            if (!"Bearer 123456".equals(token)) {
                response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
                return false;
            }
    
            // Token 校验通过
            return true;
        }
    }
    ```

4. 注册拦截器；创建配置类

    ```java
    @Configuration
    public class WebConfig implements WebMvcConfigurer {
    
        private final TokenInterceptor tokenInterceptor;
    
        public WebConfig(TokenInterceptor tokenInterceptor) {
            this.tokenInterceptor = tokenInterceptor;
        }
    
        @Override
        public void addInterceptors(InterceptorRegistry registry) {
    
            registry.addInterceptor(tokenInterceptor)
                    .addPathPatterns("/**");
        }
    }
    ```

### `Servlet`

```java
@WebServlet("/login")
public class LoginServlet extends HttpServlet {

    protected void doPost(
            HttpServletRequest request,
            HttpServletResponse response
    ) {
        
        // 对象需要自己创建
        UserService userService = new UserService();

        userService.login();
    }
}
```

# 为什么要使用 `Spring`

1. `IOC`（控制反转）：对象创建权从程序员手里交给 `Spring`

    `UserService` 对象由 `Spring` 创建，然后放入 `IOC` 容器统一管理

    ```java
    @Service
    public class UserService {
    }
    ```

    > `Spring` 启动后 -> 发现 `@Service` -> 创建 `UserService` 对象 -> 放入 `IOC` 容器

2. `DI`：依赖注入，`Spring` 自动把一个对象所依赖的其他对象注入进去（`@Autowired`），不用再不断地 `new`

    ```java
    @Service
    public class UserService {
    
        private final UserDao userDao;
    
        // 在构造方法中自动注入 userDao，只有一个构造方法时，可以省略 @Autowired 注解
        // @Autowired
        public UserService(UserDao userDao) {
            this.userDao = userDao;
        }
    }
    ```

    发现 `UserService`，发现它需要 `UserDao`，从 `IOC` 容器找到 `UserDao`，注入进去

3. `AOP`（面向切面编程）

    ```java
    @Aspect
    @Component
    public class LogAspect {
    
        @Before("execution(* com.example.service.*.*(..))")
        public void log() {
    
            System.out.println("记录日志");
    
        }
    }
    ```

4. 声明式事务

    ```java
    @Transactional
    public void createOrder() {
    
        // 扣库存
    
        // 创建订单
    
        // 扣余额
    }
    ```




# 一、`SpringBoot`

>   [spring-boot 开发文档](https://docs.spring.io/spring-boot/ "spring-boot")、[spring-boot2.7.8 开发文档](https://docs.spring.io/spring-boot/docs/2.7.8/reference/html/ "spring-boot2.7.8")
>
>   `SpringBoot2` 要求 `Java8+` 和 `Maven3.3+`
>
>   `SpringBoot2.7.8` 要求 `Java8+` 和 `Maven3.5+`

`Spring` 很强大，但是配置特别麻烦，需要特别多的 `xml` 配置

`Spring Boot` 是建立在 `Spring` 之上的，解决了**使用 `Spring` 太麻烦的问题**

1. 自动配置：根据项目依赖自动配置相关组件

2. `Starter`

    例如 `spring-boot-starter-web` 自动引入 `Web` 开发需要的大量依赖

3. `SpringBoot` 内嵌 `Tomcat`

    通常不需要再单独安装外部 `Tomcat` 然后部署 `WAR` 包



## `1.1` 配置文件

[SpringBoot 官方配置参数](https://docs.spring.io/spring-boot/docs/2.7.8/reference/html/application-properties.html#appendix.application-properties "SpringBoot 配置参数")

`SpringBoot` 配置文件的加载顺序

| 配置文件                        | 优先级 |
| ------------------------------- | ------ |
| `application.properties`        | 高     |
| `application.yml`（一般用这个） | 中     |
| `application.yaml`              | 低     |

```tex
my-project/
├── config/                              【包外，优先级高】
│   ├── application-prod.yml             profile 配置
│   └── application.yml                  默认配置
├── application.yml                      【包外根目录，优先级中】
└── src/main/resources/                  【包内，优先级低】
    ├── config/
    │   └── application.yml              【优先级比 resources/ 直接目录下的高一点】
    └── application.yml
```



## `1.2` `pom` 依赖版本

`poml` 文件父依赖 `spring-boot-starter-parent` 的父依赖 `spring-boot-dependencies` 中管理了官方依赖的仲裁版本机制

如果官方没有版本仲裁，需要自己指定依赖版本

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>2.7.18</version>
    <relativePath/> <!-- lookup parent from repository -->
</parent>
    
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-dependencies</artifactId>
    <version>2.7.18</version>
</parent>
```



### 自定义依赖版本

1.   使用 `dependencyManagement` 统一管理版本（多模块推荐）

     **多模块**项目、需要统一管理依赖版本

     ```xml
     <!-- 父模块 POM 定义版本 -->
     <properties>
         <mysql.version>8.4.6</mysql.version>
     </properties>
     
     <dependencyManagement>
         <dependencies>
             <!-- 统一管理 MySQL 驱动版本 -->
             <dependency>
                 <groupId>com.mysql</groupId>
                 <artifactId>mysql-connector-j</artifactId>
                 <version>${mysql.version}</version>
             </dependency>
         </dependencies>
     </dependencyManagement>
     ```

     ```xml
     <!-- 子模块 POM：实际引入依赖 -->
     <dependencies>
         <!-- 实际引入依赖，不再需要写 version -->
         <dependency>
             <groupId>com.mysql</groupId>
             <artifactId>mysql-connector-j</artifactId>
         </dependency>
     </dependencies>
     ```

2.   使用 `properties` 自定义版本（单模块推荐）

     只有**一个模块**的项目、需要方便修改版本号

     ```xml
     <properties>
         <java.version>17</java.version>
         <mysql.version>8.4.6</mysql.version>
     </properties>
     
     <dependencies>
         <!-- MySQL 驱动 -->
         <dependency>
             <groupId>com.mysql</groupId>
             <artifactId>mysql-connector-j</artifactId>
             <version>${mysql.version}</version>
         </dependency>
     </dependencies>
     ```

     以后需要升级驱动，只需修改 `<mysql.version>` 的值，不用逐个修改依赖声明

3.   直接声明 `version`（不推荐）

     优点是简单直观；缺点是依赖增多后，版本分散在各处，不利于统一维护

     ```xml
     <dependency>
         <groupId>com.mysql</groupId>
         <artifactId>mysql-connector-j</artifactId>
         <version>8.4.6</version>
     </dependency>
     ```



### `starter` 说明

-   官方 `starter` 的 `artifactId` 标识符都是 `spring-boot-starter-*` 的形式，如 `spring-boot-starter-web`
-   第三方的 `starter` 的 `artifactId` 标识符都是 `*-spring-boot-starter` 的形式，如 `druid-spring-boot-starter`

## `1.4` 日志配置

### 日志格式

默认输出格式：

- 时间和日期：毫秒级精度
- 日志级别：`ERROR`, `WARN`, `INFO`, `DEBUG`, `or TRACE`
- 进程 ID
- ---： 消息分割符
- 线程名： 使用[]包含
- `Logger` 名： 通常是产生日志的**类名**
- 消息： 日志记录的内容



指定日志文件路径（默认项目当前目录）：

```properties
logging.file.path=D://
```

指定日志文件名字：

```properties
logging.file.name=spring.log
```



### 日志的归档及切割(基于 `SpringBoot3` 默认的 `logback` 日志)

- 归档：日志存档的文件名格式(默认值：`${LOG_FILE}.%d{yyyy-MM-dd}.%i.gz)`

  ```properties
  logging.logback.rollingpolicy.file-name-pattern=${LOG_FILE}.%d{yyyy-MM-dd}.%i.gz
  ```

- 切割：存档前，每个日志文件的最大大小（默认值：10MB）

  ```properties
  logging.logback.rollingpolicy.max-file-size=10MB
  ```

- 应用启动时是否清除以前存档（默认值：false）

  ```properties
  logging.logback.rollingpolicy.clean-history-on-start=false
  ```

- 日志文件被删除之前，可以容纳的最大大小（默认值：0B）。设置1GB则磁盘存储超过 1GB 日志后就会删除旧日志文件

  ```properties
  logging.logback.rollingpolicy.total-size-cap=1GB
  ```

- 日志文件保存的最大天数(默认值：7)

  ```properties
  logging.logback.rollingpolicy.max-history=30
  ```

其他日志框架需要自己建立 `xml` 文件配，如 `log4j2.xml` 或 `log4j2-spring.xml`

导入其他的日志框架：

1. 导入任何第三方框架，先排除它的日志包，因为Boot底层控制好了日志
2. 修改 `application.properties` 配置文件，就可以调整日志的所有行为。如果不够，可以编写日志框架自己的配置文件放在类路径下就行，比如`logback-spring.xml`，`log4j2-spring.xml`
3. 如需对接**专业日志系统**，也只需要把 `logback` 记录的**日志**灌倒 **`kafka`**之类的中间件，这和 `SpringBoot` 没关系，都是日志框架自己的配置，**修改配置文件即可**
4. **业务中使用 `slf4j-api` 记录日志。不要再 `sout` 了**

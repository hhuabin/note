>   前后端分离后好像使用 `SpringWeb` 比较少，安安分分写接口就行

# 一、配置静态资源规则

## 1.1 默认静态资源映射规则

`Spring Boot` 默认配置了两条静态资源映射规则：

1.   规则一：普通静态资源映射

     -   访问路径：`/**`

     -   默认查找以下四个目录：

         | 资源位置                         | 说明                  |
         | -------------------------------- | --------------------- |
         | `classpath:/META-INF/resources/` | `META-INF `下的资源   |
         | `classpath:/resources/`          | `resources` 目录      |
         | `classpath:/static/`             | `static` 目录（推荐） |
         | `classpath:/public/`             | `public` 目录         |

         例如，将 `logo.png` 放在 `src/main/resources/static/images/` 下，可以通过 `/images/logo.png` 访问

2.   规则二：`WebJars` 资源映射

     -   访问路径：`/webjars/**`

     -   资源位置：`classpath:/META-INF/resources/webjars/`

     通过 `Maven` 引入 `WebJars` 依赖，即可使用对应的前端静态资源



## 1.2 静态资源缓存配置

`Spring Boot` 默认提供静态资源缓存机制，可以通过配置文件 `application.yml` 中的 `spring.web.resources.cache` 进行配置。

常用配置：

| 配置项              | 说明                                 |
| ------------------- | ------------------------------------ |
| `period`            | 设置缓存周期，单位为秒               |
| `cachecontrol`      | 设置 `HTTP` 缓存控制策略             |
| `use-last-modified` | 是否使用资源最后修改时间进行缓存验证 |

配置示例：

```yaml
spring:
  web:
    resources:
      cache:
        period: 3600
        cachecontrol:
          max-age: 3600
          cache-public: true
        use-last-modified: true
```

说明：

-   `period`：设置资源缓存有效期，这里为 3600 秒
-   `cachecontrol`：控制 `HTTP` 缓存行为，通过响应头 `Cache-Control` 实现
-   `use-last-modified`：启用 `Last-Modified` 和 `If-Modified-Since` 缓存验证机制



## 1.3 自定义静态资源配置

**自定义静态资源目录**

通过 `spring.web.resources.static-locations` 修改静态资源查找位置

```yaml
spring:
  web:
    resources:
      static-locations:
        - classpath:/static/
        - file:D:/upload/
```

注意：自定义该配置后，会替换默认的资源位置，需要自行补充想保留的目录

**自定义静态资源访问路径**

通过 `WebMvcConfigurer` 的 `addResourceHandlers()` 方法配置：

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/assets/**")
                .addResourceLocations("classpath:/static/");
    }
}
```

访问 `/assets/images/logo.png`，会查找 `static/images/logo.png`。

## 1.4 注意事项

-   `Spring Boot` 默认已经配置静态资源映射，通常不需要手动配置
-   `@EnableWebMvc` 会使 `Spring Boot` 的 `MVC` 自动配置退让，一般不要随意添加
-   仅需要自定义静态资源、拦截器、跨域等配置时，实现 `WebMvcConfigurer` 即可，无需添加 `@EnableWebMvc`



# 二、路径匹配

`Spring5.3` 之后加入了更多的请求路径匹配的实现策略；

以前只支持 `AntPathMatcher` 策略, 现在提供了 **`PathPatternParser`** 策略。并且可以让我们指定到底使用那种策略。



## 2.1 `Ant` 风格路径匹配

`Ant` 风格的路径模式语法具有以下规则：

1.  `*`：表示任意数量的字符
2.  `?`：表示任意一个字符
3.  `*`：表示任意数量的目录
4.  `{}`：表示一个命名的模式占位符
5.  `[]`：表示字符集合，例如 `[a-z]` 表示小写字母

例如：

- `*.html`：匹配任意名称，扩展名为 `.html` 的文件
- `/folder1/*/*.java`：匹配在 `folder1` 目录下的任意两级目录下的 `.java` 文件
- `/folder2/**/*.jsp`：匹配在 `folder2` 目录下任意目录深度的 `.jsp` 文件
- `/{type}/{id}.html`：匹配任意文件名为 `{id}.html`，在任意命名的 `{type}` 目录下的文件

>   注意：`Ant` 风格的路径模式语法中的特殊字符需要转义，如：

- 要匹配文件路径中的星号，则需要转义为 `\*`
- 要匹配文件路径中的问号，则需要转义为 `\?`

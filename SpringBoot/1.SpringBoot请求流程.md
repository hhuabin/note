

# 请求流程图

**`Spring Boot` 接收并处理一次前端 `HTTP` 请求** 理解成一条流水线

```java
            浏览器 / 前端
                 │
                 ▼
    	Web服务器（可选：Nginx）
    			 │
                 ▼
       Tomcat（Spring Boot 内嵌服务器）
                 │
                 ▼
            Filter（过滤器）
                 │
                 ▼
    DispatcherServlet（Spring MVC 核心）
                 │
                 ▼
    HandlerMapping（找到对应 Controller 方法）
                 │
                 ▼
     Interceptor preHandle()（拦截器）
                 │
                 ▼
            Controller
                 │
                 ▼
              Service
                 │
                 ▼
        DAO / Mapper / Repository
                 │
                 ▼
               MySQL
```

> `Tomcat` 接收请求 → `Filter` → `DispatcherServlet` 分发 → `Interceptor` → `Controller` → `Service` → `Mapper` → 数据库 → 原路返回 → `Java` 对象转换 `JSON` → 前端接收。

请求大体分三层

1. `Servlet`：`Tomcat`、`Filter`
2. `MVC`：`DispatcherServlet`、`HandlerMapping`、`Interceptor`、`Controller`
3. 响应层：`MySQL`



## 1.`Tomcat` 接收请求

`SpringBoot` 内嵌了 `Tomcat`，`Tomcat` 是最先真正接收到 `HTTP` 请求的 `Java Web` 容器

`HTTP` 请求到这里会被包装成 `HttpServletRequest`、`HttpServletResponse`，`Tomcat` 只负责接待请求，不处理



## 2.`Filter`（过滤器）

`Filter` 在请求进入 `Servlet` 前进行拦截处理，在响应返回给客户端前也能进行处理

```java
@WebFilter("/*")
public class MyFilter implements Filter {

    @Override
    public void doFilter(
            ServletRequest request,
            ServletResponse response,
            FilterChain chain
    ) {
        
        System.out.println("Filter 执行");

        chain.doFilter(request, response);
    }
}
```

| `Filter`功能 | 例子          |
| ------------ | ------------- |
| 编码处理     | UTF-8         |
| 跨域         | CORS          |
| 请求日志     | 记录 URL      |
| 权限处理     | Token         |
| 请求包装     | 修改 Request  |
| 响应包装     | 修改 Response |



## 3.`DispatcherServlet`

`Spring MVC` 的总调度中心。请求进入 `Spring MVC` 后，`DispatcherServlet` 会想：这个请求应该交给哪个 `Controller`



## 4.`HandlerMapping`

查找路由：`Spring` 会根据 **请求路径、请求方式** 查找对应的 `Controller`；`Spring` 会匹配 `@GetMapping("/{id}")`，也就是 `HandlerMapping`

```java
@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping("/{id}")
    public User getUser(@PathVariable Long id) {
        return new User();
    }
}
```



## 5.`Interceptor`

`Interceptor` 主要有三个方法

1. `preHandle()`
2. `postHandle()`
3. `afterCompletion()`

```java
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler
    ) {
        System.out.println("Controller 执行之前");

        String token = request.getHeader("Authorization");

        if (token == null) {
            response.setStatus(401);
            // 返回 false 直接拦截，请求结束，不再往下执行 Controller
            return false;
        }

        return true;
    }
}
```

```java
// 执行顺序
preHandle()
 ↓
Controller
 ↓
postHandle()
 ↓
afterCompletion()
```

`Interceptor` 常见用途有：

1. 登录验证
2. 权限验证
3. Token 验证
4. 请求日志
5. 接口耗时统计



## 6.`Controller`

框架从请求里抠出 `@PathVariable `、`@RequestParam`、`@RequestBody` 塞进方法参数

1. `@PathVariable`：路径参数；如 `@GetMapping("/users/{id}")` 的 `id`
2. `@RequestParam`：请求参数；如 `/users?page=1&size=10` 的 `page` 和 `size`
3. `@RequestBody`：`JSON` 请求体；如 `@RequestBody User user`

```java
@RestController
@RequestMapping("/users")
public class UserController {
    
    @Autowired
    private UserService userService;

    @GetMapping("/{id}")
    public User getUser(@PathVariable Long id) {

        return userService.getUserById(id);
    }
}
```

`Controller` 的职责主要是：

1. 接收请求
2. 获取参数
3. 调用 `Service`
4. 返回结果

一般不建议在 `Controller` 写大量业务逻辑



## 7.`Service`

```java
@Service
public class UserService {

    @Autowired
    private UserMapper userMapper;

    public User getUserById(Long id) {

        return userMapper.selectById(id);
    }
}
```

Service 通常处理：

1. 业务逻辑
2. 事务
3. 数据组合
4. 数据校验
5. 调用其他服务



## 8.`DAO / Mapper / Repository`

```java
@Mapper
public interface UserMapper {

    User selectById(Long id);
}
```



## 9.`MySQL`

```sql
SELECT * FROM user WHERE id = 1
```



## 10.`Controller` 返回 `JSON`

```java
@GetMapping("/users/{id}")
public User getUser(@PathVariable Long id) {

    return userService.getUserById(id);
}
```

返回的是 `Java` 对象 `User`。但前端需要的是 `JSON`：

```json
{
    "id": 1,
    "username": "zhangsan",
    "age": 18
}
```

这时候 `Spring` 会使用 `HttpMessageConverter` 进行转换

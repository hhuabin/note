# 一、`Lombok` 简化 `JavaBean` 开发

优点

-   **代码简洁**：大幅减少样板代码
-   **易维护**：改字段名不用手动改一堆方法

缺点：

-   **强依赖 `IDE` 插件**：虽然编译能过，但 `IDE` 不装插件会报错、没提示、无法跳转**（`Idea` 需要到 `Plugins` 中下载 `Lombok` 插件）**
-   破坏封装：`@Data` 无脑生成所有 setter，可能暴露不该暴露的字段
-   升级风险：`Lombok` 深度依赖编译器内部 `API`（如 `javac` 的 `AST`），**`JDK` 升级经常导致兼容问题**（如 `JDK 17、21` 都出过坑）
-   **`@Builder` 与构造的坑**：比如 `@Builder` 默认生成全参构造，可能和你手写的构造函数冲突；`@Data` + `@Builder` 组合有时需要补 `@NoArgsConstructor`



## `1.1` 引入依赖

```xml
<dependencies>
    <!-- lombok 简化 Java Bean 开发 -->
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <!-- Spring Boot 父工程已经管理 Lombok 版本 -->
        <!-- 依赖在编译阶段有效 -->
        <optional>true</optional>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
            <!-- Lombok 只作用在编译器，运行时不需要，需要手动排除该包 -->
            <configuration>
                <excludes>
                    <exclude>
                        <groupId>org.projectlombok</groupId>
                        <artifactId>lombok</artifactId>
                    </exclude>
                </excludes>
            </configuration>
        </plugin>
    </plugins>
</build>
```

>   `<optional>true</optional>` 是 `Maven` 中依赖的可选依赖配置，意思是：当前项目使用这个依赖，但默认**不把它作为依赖传递给下游项目**
>
>   简单说就是：当前项目可以使用 `Lombok`，但依赖当前项目的其他项目，不会因为依赖传递而自动引入 `Lombok`，

### `IDE` 配置

以 `IntelliJ IDEA` 为例：

1.  打开 `Settings`
2.  进入 `Plugins`，搜索并安装 `Lombok` 插件（如果尚未安装）
3.  进入 `Build, Execution, Deployment → Compiler → Annotation Processors`
4.  勾选 `Enable annotation processing`
5.  重新构建项目

不同版本的 `IDEA` 菜单位置可能略有差异。

区分两个概念：

-   `Lombok` 依赖：让项目编译时能够使用 `Lombok`
-   `IDE` 插件及注解处理配置：帮助编辑器正确识别生成的方法，并支持代码分析



## `1.2` 最常用的 `Lombok` 注解

| 注解                       | 中文理解               | 主要作用                         |
| -------------------------- | ---------------------- | -------------------------------- |
| `@Getter`                  | `Getter` 生成注解      | 生成 `getter` 方法               |
| `@Setter`                  | `Setter` 生成注解      | 生成 `setter` 方法               |
| `@ToString`                | 字符串表示生成注解     | 生成 `toString()`                |
| `@EqualsAndHashCode`       | 相等性与哈希码生成注解 | 生成 `equals()`、`hashCode()`    |
| `@Data`                    | 数据类组合注解         | 集合多种常用功能                 |
| `@NoArgsConstructor`       | 无参构造注解           | 生成无参构造方法                 |
| `@AllArgsConstructor`      | 全参构造注解           | 生成包含所有实例字段的构造方法   |
| `@RequiredArgsConstructor` | 必需参数构造注解       | 为指定的必需字段生成构造方法     |
| `@NonNull`                 | 非空检查注解           | 在指定位置生成空值检查           |
| `@Value`                   | 不可变数据类注解       | 生成偏向不可变对象的代码         |
| **`@Slf4j`**               | `SLF4J` 日志注解       | 自动生成 `log` 对象              |
| `@Builder`                 | 建造者模式注解         | 链式创建对象                     |
| `@SuperBuilder`            | 继承型建造者注解       | 支持父子类字段的 `Builder`       |
| `@Accessors`               | 访问器配置注解         | 自定义 `Getter`、`Setter` 的形式 |



### `@Getter` 和 `@Setter`

1.   既可以放在类上，也可以放在字段上

     ```java
     @Getter
     public class User {
     
         @Setter
         private Long id;
     
         private String username;
     }
     ```

2.   可以指定访问权限

     ```java
     @Getter
     @Setter
     public class User {
     
         // 这里 password 不会生成 Getter 和 Setter
         @Getter(AccessLevel.NONE)
         @Setter(AccessLevel.NONE)
         private String password;
     }
     ```

     常用的访问权限有：

     | 配置                    | 生成方法的访问权限 |
     | ----------------------- | ------------------ |
     | `AccessLevel.PUBLIC`    | `public`           |
     | `AccessLevel.PROTECTED` | `protected`        |
     | `AccessLevel.PACKAGE`   | 默认包访问权限     |
     | `AccessLevel.PRIVATE`   | `private`          |
     | `AccessLevel.NONE`      | 不生成对应方法     |



### `@ToString`

自动生成对象的字符串表示

1.   简单使用

     ```java
     import lombok.ToString;
     
     @ToString
     public class User {
     
         private Long id;
     
         private String username;
     }
     ```

     ```java
     User user = new User();
     System.out.println(user);      // User(id=null, username=null)
     ```

2.   `@ToString.Exclude` 排除敏感字段

     ```java
     @ToString
     public class User {
     
         private Long id;
     
         private String username;
     
         @ToString.Exclude
         private String password;
     }
     ```

     这样 `toString()` 就不会输出 `password`

3.   配置只包含指定字段

     ```java
     @ToString(onlyExplicitlyIncluded = true)
     public class User {
     
         @ToString.Include
         private Long id;
     
         private String username;
     
         private String password;
     }
     ```

     此时字符串表示只包含 `id`

     注意： 密码、令牌、身份证号等敏感信息，不应随意输出到日志中。使用 `@Data` 时尤其要留意这一点，因为它默认包含 `@ToString` 的功能



### `@EqualsAndHashCode`

用于自动生成 `equals()` 和 `hashCode()`

1.   默认会根据参与生成的字段计算相等性

     ```java
     import lombok.EqualsAndHashCode;
     
     @EqualsAndHashCode
     public class User {
     
         private Long id;
     
         private String username;
     }
     ```

     ```java
     User user1 = new User();
     User user2 = new User();
     
     // 两个对象字段值相同的情况下
     // equals() 可以返回 true
     ```

     这与 `Java` 默认的 `Object.equals()` 不同：默认实现通常比较对象身份，而 `Lombok` 生成的实现比较相关字段值

2.   排除字段

     ```java
     @EqualsAndHashCode
     public class User {
     
         private Long id;
     
         private String username;
     
         @EqualsAndHashCode.Exclude
         private String lastLoginIp;
     }
     ```

     `lastLoginIp` 不参与相等性和哈希码计算

实际开发建议： 数据库实体类要谨慎选择参与比较的字段。特别是关联对象、双向关系和可变字段，可能导致递归、性能问题或对象放入 `HashSet`、`HashMap` 后行为异常



### `@Data` 数据类组合注解

`@Data` 比较重，不太建议使用该注解，需要什么加什么即可

`@Data` 组合了以下功能：

| 组合功能                   | 具体作用                                 |
| -------------------------- | ---------------------------------------- |
| `@Getter`                  | 所有**非静态**字段生成 `Getter`          |
| `@Setter`                  | 所有非静态、非 `final` 字段生成 `Setter` |
| `@ToString`                | 生成 `toString()`                        |
| `@EqualsAndHashCode`       | 生成 `equals()` 和 `hashCode()`          |
| `@RequiredArgsConstructor` | 按必需字段生成构造方法                   |

>   `@Data` 不等于 `@NoArgsConstructor + @AllArgsConstructor`

```java
import lombok.Data;

@Data
public class User {

    private final Long id;

    private String username;
}
```

会生成：

```java
public class User {

    private final Long id;
    private String username;

    // 1. 因为 id 是 final，@Data 内含的 @RequiredArgsConstructor
    //    生成一个只含 id 的构造器（没有无参构造！）
    public User(Long id) {
        this.id = id;
    }

    // 2. id 是 final，只有 getter，没有 setter
    public Long getId() {
        return id;
    }

    // 3. username 有 getter 和 setter
    public String getUsername() {
        return username;
    }

    public void setUsername(String username) {
        this.username = username;
    }

    // 4. equals / hashCode，包含 id 和 username
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        User user = (User) o;
        return Objects.equals(id, user.id)
                && Objects.equals(username, user.username);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, username);
    }

    // 5. toString，包含 id 和 username
    @Override
    public String toString() {
        return "User{" +
                "id=" + id +
                ", username='" + username + '\'' +
                '}';
    }
}
```

`id` 是 `final` 字段，`Lombok` 会将其纳入必需参数构造方法；`username` 则可以通过 `Setter` 修改

如果类中已经显式声明构造方法，`@Data` 不会再生成它原本计划生成的构造方法



### `@NoArgsConstructor` 无参构造注解

```java
@NoArgsConstructor
public class User {

    private Long id;

    private String username;
}
```

生成的效果相当于：

```java
public User() {
}
```



### `@AllArgsConstructor` 全参构造注解

>   推荐结合 `@NoArgsConstructor` 一起使用

```java
@AllArgsConstructor
public class User {

    private Long id;

    private String username;
}
```

相当于：

```java
public User(Long id, String username) {
    this.id = id;
    this.username = username;
}
```

-   可以指定构造方法的访问权限：

    ```java
    @NoArgsConstructor(access = AccessLevel.PROTECTED)
    ```

    在某些 `ORM` 实体设计中，可以使用受保护的无参构造方法



### `@RequiredArgsConstructor` 必需参数构造注解

>   推荐结合 `@NoArgsConstructor` 一起使用

```java
@RequiredArgsConstructor
public class User {

    private final Long id;

    @NonNull
    private String username;

    private String address;
}
```

生成的构造方法相当于：

```java
public User(Long id, String username) {
    this.id = id;
    this.username = username;

    if (username == null) {
        throw new NullPointerException("username is marked non-null but is null");
    }
}
```

-   `final` 字段会成为构造参数
-   未初始化的 `@NonNull` 字段会成为构造参数
-   普通字段 `address` 不会成为构造参数

>   | 注解                       | 参数范围     | 典型用途               |
>   | -------------------------- | ------------ | ---------------------- |
>   | `@NoArgsConstructor`       | 无参数       | 需要无参实例化的对象   |
>   | `@AllArgsConstructor`      | 所有实例字段 | 明确需要全参构造的对象 |
>   | `@RequiredArgsConstructor` | 必需字段     | 构造注入、不可变对象   |



### `@NonNull` 非空检查注解

用于要求指定字段、参数或方法参数不为 `null`，`Lombok` 会在支持的位置生成空值检查

```java
import lombok.NonNull;
import lombok.RequiredArgsConstructor;

@RequiredArgsConstructor
public class UserService {

    @NonNull
    private final UserMapper userMapper;

    public void findUser(@NonNull Long userId) {
        System.out.println(userId);
    }
}
```

-   字段上的 `@NonNull`：配合 `@RequiredArgsConstructor`，构造时检查传入值
-   参数上的 `@NonNull`：方法执行时检查传入值

>   注意，`@NonNull` 并不是完整的参数校验框架。它不能代替 `Spring Validation` 中的 `@NotNull`、`@NotBlank` 等注解，也不会自动校验字符串是否为空白



### `@Value` 不可变数据类注解

`@Value` 适合创建偏向不可变的数据对象

```java
import lombok.Value;

@Value
public class UserInfo {

    Long id;

    String username;
}
```

默认会生成：

-   所有字段的 `Getter`
-   基于字段的 `equals()`、`hashCode()`
-   `toString()`
-   包级别的全参构造方法
-   `private final` 字段

与 `@Data` 对比：

| 对比项         | `@Data`      | `@Value`                   |
| -------------- | ------------ | -------------------------- |
| 字段默认设计   | 可变         | 不可变                     |
| Getter         | 有           | 有                         |
| Setter         | 通常有       | 无                         |
| 字段默认修饰符 | 按原定义     | `private final`            |
| 典型用途       | 普通数据对象 | 不希望创建后修改的数据对象 |

注意，`final` 只限制字段重新赋值，不代表字段引用的对象一定不可变



### `@Slf4j` 日志注解

用于自动生成日志对象，`Spring Boot` 项目中几乎随处可见

```java
import lombok.extern.slf4j.Slf4j;

@Slf4j
public class UserService {

    public void getUser() {
        log.info("查询用户");
        log.warn("用户不存在");
        log.error("查询用户失败");
    }
}
```

| 方法          | 适用场景                 |
| ------------- | ------------------------ |
| `log.trace()` | 非常细粒度的跟踪信息     |
| `log.debug()` | 调试信息                 |
| `log.info()`  | 正常业务运行信息         |
| `log.warn()`  | 潜在异常或需要关注的问题 |
| `log.error()` | 错误及异常               |

1.   `{}` 是 `SLF4J` 的参数占位符

     ```java
     try {
         // 业务操作
     } catch (Exception e) {
         log.error("查询用户失败，userId={}", userId, e);
         throw e;
     }
     ```

     不要只写 `log.error("查询失败：" + e.getMessage())`，否则通常无法获得完整的异常堆栈





### `@Builder` 建造者模式注解

>   推荐结合 `@NoArgsConstructor` 一起使用

当一个类有很多字段时，`Builder` 通常比构造方法更容易阅读

```java
import lombok.Builder;
import lombok.Getter;

@Getter
@Builder
public class User {

    private Long id;

    private String username;

    private String password;

    private String email;
}
```

1.   不使用 `Builder`，需要直接 `new` 对象

     ```java
     User user = new User(
         1L,
         "zhangsan",
         "123456",
         "zhangsan@example.com"
     );
     ```

2.   使用 `Builder` 创建对象

     ```java
     User user = User.builder()
             .id(1L)
             .username("zhangsan")
             .password("123456")
             .email("zhangsan@example.com")
             .build();
     ```

     -   `User.builder()` 创建 `Builder` 对象
     -   `.id(...)`、`.username(...)` 等方法设置字段
     -   `.build()` 创建最终的 `User` 对象

3.   `@Builder.Default`

     ```java
     @Builder
     public class User {
     
         private Long id;
     
         private String username;
     
         @Builder.Default
         private Integer status = 1;
     }
     ```

     ```java
     User user = User.builder()
             .username("zhangsan")
             .build();
     ```

     此时 `status` 为 `1`



### `@Accessors` 访问器配置注解

用于自定义 `Getter`、`Setter` 的命名方式，属于比较进阶的功能

```java
import lombok.Getter;
import lombok.Setter;
import lombok.experimental.Accessors;

@Getter
@Setter
@Accessors(chain = true)
public class User {

    private Long id;

    private String username;
}
```

原本的 `Setter` 返回 `void`，启用 `chain = true` 后会返回当前对象，因此可以这样调用：

```java
User user = new User()
        .setId(1L)
        .setUsername("zhangsan");
```





## `1.3` `Spring Boot` 项目中怎么组合使用?

1.   `Entity / DO`：数据库实体

     表示数据库中的数据，通常需要 `Getter`、`Setter`，并根据 `ORM` 需求提供构造方法

     ```java
     @Getter
     @Setter
     @NoArgsConstructor
     public class User {
         private Long id;
         private String username;
     }
     ```

2.   `DTO`：请求参数对象

     用于接收前端提交的数据。可配合校验注解。

     ```java
     @Data
     public class CreateUserRequest {
         private String username;
         private String password;
     }
     ```

3.   `VO / Response`：响应对象

     返回给前端的数据，优先考虑只读或不可变设计

     ```java
     @Getter
     @Builder
     public class UserResponse {
         private Long id;
         private String username;
     }
     ```

4.   `Service`：业务逻辑层

     通常使用构造器注入依赖，并通过日志记录业务过程

     ```java
     @Slf4j
     @Service
     @RequiredArgsConstructor
     public class UserService {
     
         private final UserMapper userMapper;
     }
     ```

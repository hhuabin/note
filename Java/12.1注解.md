# 1.基本注解

`JDK8` 中提供了5种基本注解

| 注解                   | 说明                                               |
| ---------------------- | -------------------------------------------------- |
| `@Deprecated`          | 表示某个程序元素，如类，方法等已过时               |
| ``@Override`           | 该注解只能用于方法，限定必须覆盖父类中的方法       |
| `@SuppressWarnings`    | 该注解用于抑制警告信息的出现，即不允许出现警告信息 |
| `@SafeVarargs`         | 用于抑制堆警告                                     |
| `@FunctionalInterfase` | 用于指定某个接口必须是函数式接口                   |



# 2.元注解

1. `@Target` 限制注解的使用范围。

   取值在枚举 `java.lang.annotation.ElementType` 中。如 `@Target(ElementType.TYPE)`、`@Target(ElementType.METHOD)`

   | 作用范围          | 说明                               |
   | ----------------- | ---------------------------------- |
   | `CONSTRUCTOR`     | 只能用在构造方法的声明中           |
   | `FIELD`           | 只能用在成员变量声明上             |
   | `LOCAL_VARIABLE`  | 只能用在局部变量声明上             |
   | `METHOD`          | 只能用在方法声明上                 |
   | `PACKAGE`         | 只能用在包的声明上                 |
   | `PARAMETER`       | 只能用在参数的声明上               |
   | `TYPE_PARAMETER`  | 只能用在类型参数的声明上           |
   | `TYPEUSE`         | 只能用在类型注解的声明上           |
   | `TYPE`            | 只能用在类、接口或枚举类型的声明上 |
   | `ANNOTATION_TYPE` | 只能用在注解声明上                 |

2. `@Retention` 说明注解的保存范围

   作用范围的取值在 枚举 `java.lang.annotation.RetentionPolicy` 中，如 `@Retention(RetentionPolicy.RUNTIME)`

   | 生命周期  | 说明                                                         |
   | --------- | ------------------------------------------------------------ |
   | `SOURCE`  | 编译后消失：注解只存在于源代码 `.java` 文件中,在编译后不会保存在类文件(`.class`)中 |
   | `CLASS`   | 保存到 `.class` 文件（**默认值**）：在编译时将注解保存在字节码文件中，即编译器把注解记录在 `.class` 文件中。当运行 `Java` 程序时，`JVM` 不会加载此注解信息 |
   | `RUNTIME` | 程序运行时仍然存在：编译器把注解记录在 `class` 文件中,当运行 `Java` 程序时，`JVM` 会加载注解信息，并可以通过反射获取注解信息 |

3. `@Documented`：用于指定被修饰的注解可被 `javadoc.exe` 工具提取成文档

4. `@Inherited`：用于描述一个父类的注解可以被子类继承

5. `@Repeatable`： 用于开发重复注解

6. 类型注解



# 3.`Java` 原生自定义注解

`Java` 从 `Java 5` 开始就原生支持自定义注解

使用 `@interface` 就相当于继承了 **`java.lang.annotation.Annotation`** 接口，并且不能再去继承别的 类 或者 接口。注解的成员由未实现的方法组成。

```java
[public] @interface 注解名 {
    数据类型 成员变量名 () [default 初始值];
    ...
}
```

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface MyAnnotation {
    String value() default "";
}
```

---

示例

1. 自定义注解：

    ```java
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.METHOD)
    public @interface MyAnnotation {
        String value() default "";
    }
    ```
    
2. 使用注解：

    ```java
    public class Demo {
        @MyAnnotation("hello")
        public void doSomething() {}
    }
    ```
    
3. 运行时读取

    ```java
    Method method = Demo.class.getMethod("doSomething");
    
    if (method.isAnnotationPresent(MyAnnotation.class)) {
        MyAnnotation anno = method.getAnnotation(MyAnnotation.class);
        System.out.println(anno.value()); // hello
    }
    ```

> 如果我们要获得的注解是配置在**方法上**的，那么我们要从 `Method` 对象上获取
>
> 如果是配置在**属性上**，就需要从该属性对应的 `Field` 对象上去获取
>
> 如果是配置在**类型上**，需要从 `Class` 对象上去获取
>
> 总之在谁身上，就从谁身上去获取



## `3.1` 注解的作用

注解本身不会产生任何功能，它只是一个**标记 / 配置**，注解本身不会自动执行功能

要让 `@MyAnnotation` 产生效果，必须有代码去读它。两种常见方式：

1.   **运行时反射**：自己写代码扫描并处理（如上例）
2.   **编译期处理（APT）**：写 `AnnotationProcessor`，在编译时生成代码或报错，如 `Lombok`、`Dagger`、`MapStruct`
